# WarThunder Skin Manager

管理《战争雷霆》`UserSkins` 自定义涂装的桌面工具。

核心流程：**导入并解构涂装 → 存入资源库 → 按载具组织 → 部件级贴图适配（用户选择）→ 动态重写 `blk` → 以热重载友好的方式输出到游戏 `UserSkins/WTSM`**。

解决两个痛点：

1. **目录堆积导致扫描慢/崩溃**：一个载具大量皮肤全部堆在一个文件夹，游戏扫描缓慢甚至崩溃。
2. **同载具皮肤部件不齐**：例如载具 A 一个皮肤适配了导弹贴图、另一个只做了主体，导致外观不一致。

> 详细设计见 [`docs/`](docs/)。

## 技术栈

- **.NET 10 / WPF**（`net10.0-windows`）
- **CommunityToolkit.Mvvm**（`[ObservableProperty]` / `[RelayCommand]` 源生成）
- **纯 WPF**：不使用 WinForms、无第三方 UI 包、无网络依赖
  - 文件夹选择使用 .NET 8+ 内置的 `Microsoft.Win32.OpenFolderDialog`
- 界面文案全部外置为 **JSON 语言文件**（`{loc:Loc key}` 绑定）
- **SharpCompress**（压缩包导入：zip / 7z / rar / tar / gzip 等，见 §3.1）

## 运行时目录（由用户在设置中指定）

| 目录 | 说明 |
|------|------|
| **游戏 UserSkins 目录** | 程序在其下建立 `WTSM/` 作为激活输出 |
| **程序资源存储目录** | 皮肤库，可能几百 GB：`blobs/`（内容寻址去重）+ `packages/<Id>/`（blk + meta.json） |
| **程序配置目录** | 默认 `%LocalAppData%\WarThunderSkinManager` |

配置目录内容：

```
<配置目录>/
├── config.json                    # 三个目录路径、语言、导入选项记忆等
├── lang/zh-CN.json                # 语言文件（首次运行自动生成，可替换）
├── lang/_zh-CN.defaults.json      # 内置文案基线（内部文件，用于内置文案更新）
├── mappings/vehicles.json         # 载具内部标识 ↔ 显示名
├── mappings/vehicle_countries.json# 载具 → 国家（用户手动归类，优先于前缀推断）
├── mappings/part_groups.json      # 多源复用组（可选，§3.13：组内 from 的贴图可互相选用）
├── loadouts/<载具Id>.json         # 该载具激活的涂装包（{ activePackageId }）
├── ref/units.csv                  # 载具译名表（首次启动自动写出，可直接改；可单独替换更新）
├── ref/units_weaponry.csv         # 武器名表（同上）
├── ref/_units.defaults.csv        # 基线（内部文件：判断表有没有被改过，决定能否随程序更新）
├── ref/_units_weaponry.defaults.csv
└── previews/                      # 预览图缓存（png，键=涂装包 id）
```

> 部件贴图配置属于**涂装包**（`packages/<Id>/meta.json` 的 `parts`），不属于载具。
> `ref/` 里的两张表**用户表优先、内置表兜底**，替换后立即生效（无需重启）；设置页可「导出内置表」作为更新起点。

## 功能进度

**已完成**
- WPF 外壳：自定义窗口（`WindowChrome` + 自绘标题栏）、左侧图标导航、页面切换动效
- 设计系统：设计令牌、按钮/输入框/卡片/复选框/开关/滚动条等组件样式与过渡动画；**统一消息对话框**（`MessageDialog`，全程序不使用系统 `MessageBox`，破坏性确认用实心红按钮）
- 国际化：语言文件加载与 `{loc:Loc}` 绑定，切换语言刷新界面
- 配置：三个目录（配置 / 资源 / UserSkins）的读写；选择目录后自动保存
- 数据模型：`Vehicle` / `VehiclePart` / `SkinPackage` / `TexMapping` / `ActiveLoadout` / `Import` / `Country`
- blk 解析：`replace_tex` / `set_tex` → `TexMapping`，并做基础校验（`*`、扩展名、`param`、贴图存在性）
- 导入与解构服务层：递归识别 blk → 解构；**贴图存在性校验**（`to` 在 blk 同目录解析不到即标记「贴图缺失」，精确名优先、回退大小写不敏感，预览里以「缺失贴图」列体现）；贴图按 **SHA-256 内容寻址**入 `blobs/`（跨包去重、复制包零增量）；写 `packages/<Id>/source.blk` + `meta.json`；按 `from` 去 `*` 聚合成 `VehiclePart`；国家前缀自动归类；导入溯源清单
- **导入后可清理源**（导入预览勾选，默认勾选，`WTSM` 永不删）：一键导入 UserSkins → 只删贡献了导入的顶层子文件夹（根下散落的 blk 只删文件）；**导入文件夹 → 删整个源文件夹**；有导入失败的 blk 时自动跳过该处并在状态栏提示；涂装已入库，可用「导出」恢复
- 激活输出服务层：由激活包重写 `blk` + 把贴图调度到 `UserSkins/WTSM/<载具Id>/`（同盘硬链接、跨卷复制）并清理旧贴图；**贴图缺失的部件跳过不写**（避免游戏静默失败）；**保持 blk 文件名与路径不变**以热重载；二次同步幂等
- **拖入导入与压缩包导入**（§3.1）：把涂装文件夹或压缩包（可多选）拖到窗口任意位置即导入（拖拽时有提示浮层）；压缩包用 **SharpCompress** 支持 zip / 7z / rar / tar / gzip 等，先解压到 `<资源目录>/imports/extract/` 暂存区再解构，**暂存目录随后自动清理**；**受密码保护的包弹密码框**（可重试 3 次、取消则跳过该包）；预览里可选**「导入成功后删除压缩包」**（默认不勾）；建议包名取压缩包名（包内仅一个顶层文件夹时取该名）；**导入选项会被记住**（按 一键导入 UserSkins / 导入文件夹 / 压缩包 三种方式分别记忆，存 `config.json`）
- 涂装管理页：国家横条（带计数）+ 载具二级列表 + **涂装包卡片网格**（缩略图 / 半透明名称条 / 拖动排序 / 尺寸与列数自适应）；**导入预览对话框**（**同名来源自动分组、可整组改名**；显示缺失贴图数与可悬停的校验告警）
- 涂装包属性（§3.6）：自定义显示名、预览图（选择图片 / 剪贴板 / 清除）、**逐部件贴图配置**——按 `from` 从同载具各包中相同位置的贴图里挑选，**并支持跨载具复用**：同 `from` 的其他载具贴图也会进候选并标注紫色「跨载具 · 载具名」胶囊（Gaijin 就是用相同 `from` 跨载具复用贴图；同一张贴图出现在多台载具时合并为「跨载具 · XX 等 N 台载具」）；候选池由**库级部件表** `PartCatalog`（`from → 库中全部可用贴图`，库变动后自动重建）支撑（含「不设置」），**部件名右侧显示标签**（最多三个）：**武器 / 导弹**（红色，来自内置武器表 `Assets/units_weaponry.csv`）→ 按命名规律推测的**部位 / 功能**与**贴图类型**（纹理绿 / 法线黄；如「主体」「法线」）；每行另有 **`replace_tex` ⇄ `set_tex` 写入方式滑块**（首次使用弹窗说明，确认后不再提示）；保存为 `packages/<Id>/meta.json` 的 `parts`；据此可「复制包 → 换几个部件」派生新组合
- **激活与输出**（§3.8）：卡片右键**激活为当前涂装**（每个载具同时只激活一套，写入 `loadouts/<载具Id>.json`），**激活即立即输出该载具**（某载具**首次**生成 blk 时会提示去游戏里「外观 → 用户涂装」选中一次，之后切换无需重选）；**涂装包属性页保存**（改的是激活包）时也**立即输出**；**取消激活**（或删掉该载具当前激活的包）时**清空 `<UserSkins>/WTSM/<载具Id>/`**：删掉贴图但**保留一个空 blk**（游戏靠 blk 记住涂装槽位，删了每次都要在游戏里重选；空 blk = 槽位仍在、贴图回落默认），带路径越界保护。输出 = 按激活包重写 blk 并把贴图调度到 `UserSkins/WTSM/<载具Id>/`（同盘硬链接、跨卷复制、清理旧贴图）。**不提供手动「同步」按钮与自动同步 / 缓冲设置**——输出只在"激活 / 切换激活包、属性页保存、取消激活"时变化
- 涂装包操作：复制（**零字节增量**，含继承部件配置）、**导出**（§3.11，两种形式均打开**导出配置窗口**——文件夹：位置 / 是否创建文件夹 / 文件夹名；压缩包：位置 / 压缩包名 / 格式 zip·tar；共用**贴图文件命名规则**（原名 / 哈希 / 部件名，非原名时 blk 的 to 引用同步重写）；内含以名字命名的顶层文件夹，可直接分享 / 重新导入）、删除；操作走卡片右键菜单；**新建空白涂装包**（§3.4，当前载具的包计数旁「新建」）：无 `source.blk`、无贴图引用，建完即开属性界面，贴图全部从库内其他包组合（含跨载具 / 多源复用候选；导出时现场创建一行 name 的占位 blk）
- 载具管理页：**只配置载具显示数据**——显示名映射（自动保存到 `mappings/vehicles.json`）、国家手动归类（`mappings/vehicle_countries.json`，优先于前缀推断）、内部标识 / 涂装包数 / 部件结构的只读展示
- **多源复用**（§3.13，可选，默认关闭）：处理「Gaijin 贴图相同、UV 一致但部件命名不同」（如 su33 与 j15t 的机身）——设置页开启（首次开启弹知会），左侧出现「多源复用」页：把可互换的部件位置（from）分为一组（存 `mappings/part_groups.json`，一个 from 至多一组）；此后涂装包属性页选贴图时，同组其他 from（不论哪台载具）的贴图也进入候选，红色「多源 · 载具名」标注；**只扩候选不改输出模型**（写回包的仍是本部件自己的 from，删来源包不影响已引用方）
- **资源库懒加载**（§4）：`<配置目录>/index/library.json` 缓存索引快照（含每个包**解析后的映射**与文件戳），启动先出快照让界面立即可用，再在后台核对实际文件（包增删 + `meta.json`/`source.blk` 时间戳）——没变化就零扫描；两个页面共用同一份内存快照，切页只做零扫描的重新投影（无「刷新」按钮），预览图只解码当前载具并降采样；运行期间的外部改动在设置页「资源库维护」手动**全量重建**（后台执行）
- **映射文件导出 / 导入 / 合并**（§3.7，载具管理页工具栏）：导出为 JSON（按键排序，便于备份 / 换机 / 分享）；**导入** = 用文件替换当前全部映射（二次确认、危险色按钮）；**合并** = 仅文件里有的直接新增、值不同的**逐个弹窗**选「使用导入值 / 保留现有」、当前独有的保持不动；读取时忽略空键 / 空值并去首尾空白，格式不对时明确提示
- **可单独替换的内置数据表**（§3.6 / §3.7）：载具译名表 `units.csv` 与武器名表 `units_weaponry.csv` 以**嵌入资源**随程序发布，同时支持**用户表覆盖**——放到 `<配置目录>/ref/` 即生效（**立即生效，无需重启**，按「路径 + 最后写入时间」重建缓存）；设置页提供「打开目录」（不存在则建目录，表缺失时先生成一份内置默认表）与「导出内置表」便于更新
- **载具名自动识别**（§3.7）：内嵌「内部标识 → 各语言译名」表（`Assets/units.csv`，可被 `<配置目录>/ref/units.csv` 覆盖），取**短名词条 `<标识>_1`**（缺失依次回落全名 `_0` → 标识 → 商店名 `_shop`）；导入新载具时按**界面语言**自动取译名（zh-CN→简体、zh-TW→繁体、其余按语言主标签、缺失回落英文）；解析时清理源表里的**国旗占位符**（`▄`/`◔`/`␗`/私用区等，游戏字库里是小国旗、别处是乱码）与**零宽字符**；**用户自定义名优先**
- **界面语言切换**（§3.9，设置页）：**内置简体中文 + English**（默认文案均为嵌入资源 `Assets/lang/<语言代码>.json`；未翻译的 key 回落中文）+ 放进 `<配置目录>/lang/` 的语言文件；**语言显示名写在各语言文件自己里面**（`app.language.name`，语言自己写自己，缺失回退语言代码）；切换**立即生效**（全部文案刷新），且**载具自动译名按新语言重新检索**（用户映射仍最优先）、国家名等派生文案同步重建；选择持久化到 `config.json`
- **主题色**（界面设计规范 §3，设置页）：内置**默认蓝 / 翠绿 / 琥珀 / 深色**四套配色，每套一份颜色字典 `Themes/Theme.<Id>.xaml`；下拉选择后自动保存、**重启生效**（提供「重启程序」按钮）；危险色语义全主题保留
- 设置页**存储维护**：**立即回收未引用贴图**（§6.5，后台执行并给出"删除 N 个文件、释放 X"统计；只删任何包都没引用的文件与残留 `.tmp`，已输出到游戏 `UserSkins` 的贴图不受影响）；**删除涂装包时也会自动在后台回收一次**
- 设置页**危险操作**：**清除所有数据**（三重确认：警告弹窗 → 勾选范围 + 输入 `DELETE` → 最后确认），可分别清除资源库 / 配置数据 / 语言与配置 / 游戏输出 `WTSM`，只删程序自己管理的目录
