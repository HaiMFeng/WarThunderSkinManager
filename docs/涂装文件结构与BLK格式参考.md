# 战争雷霆自定义涂装：文件结构与 BLK 格式参考

> 整理自 `docs/ref/` 下的两份资料（《blk 文件书写规范总结》《教程网站参考》）以及实际示例模组的分析。
> 目的：为皮肤管理器（WarThunderSkinManager）提供可查的规范与校验依据。

---

## 1. 涂装文件总览

一个自定义涂装由 **两类文件** 组成：

| 类别 | 格式 | 作用 |
|------|------|------|
| 引导文件 | `.blk` | 告诉游戏如何识别涂装、把贴图加载到正确位置 |
| 贴图文件 | `.dds` / `.tga` | 载具涂装的实际显示效果 |

- **两者缺一不可**：缺引导文件则游戏无法识别；缺贴图文件则对应部位不显示/报错。
- `.blk` 文件名决定"这套涂装能被哪个载具使用"（见 §3）。

---

## 2. 目录结构

```
UserSkins/
└── <涂装文件夹>/                 // 名称任意，可能有多个，且可多层嵌套
     ├─ ...（可能的子目录）
     │    └─ <载具标识>.blk       // 引导文件，文件名即载具标识
     │         └─ 同目录下 *.dds  // blk 引用的贴图在【该 blk 所在目录】内查找
     ├─ <载具标识>.blk
     └─ *.dds / *.tga
```

要点：
- `UserSkins` 下是若干**涂装文件夹**（名称任意），数量可能多个，且**文件夹可多层嵌套**。
- **识别一套涂装的依据是 `.blk` 文件本身的位置**：游戏从该 blk **所在目录**出发，在其同目录内查找 `to` 引用的贴图文件；与 `UserSkins` 根或某个固定的"模组根"无关。
- 因此 blk 的 `to` 是相对其**自身所在目录**的路径，不在上层或根目录找。
- 同一目录（含嵌套子目录）下可含多个 `.blk`：同一载具家族的不同子型号（如 F-15A / F-15E / F-15J-KAI）各自一个 blk，并**共享同一批同目录的 `.dds`**（通用武器、挂架贴图在机型间复用）。
- 文件数量从 2 个到十几个以上不等，取决于制作完成度与所需修改程度。

---

## 3. 载具标识 = blk 文件名

- 涂装能被哪辆载具使用，**取决于引导文件的文件名**（去掉 `.blk` 扩展名即为载具标识）。
- 文件名正确时游戏才读取；错误则不被识别。
- 与 blk 处于多少层嵌套目录**无关**，只看文件名本身。
- 示例：`cn_vt_5.blk` → 载具 `cn_vt_5`（中国 VT-5 轻坦）；`f_15a.blk` → 载具 `f_15a`（F-15A）。

## 4. BLK 基本结构

固定以 `name:t="user"` 开头，标记这是一个可读取的自定义涂装文件。其下为若干替换/设置块。

**replace_tex（替换贴图）**

```
name:t="user"

replace_tex {
  from:t="原模型贴图名*"
  to:t="你的贴图文件.dds"
}
```

**set_tex（设置贴图，仅陆/海固定迷彩用）**

```
name:t="user"

set_tex {
  from:t="原模型贴图名*"
  to:t="你的贴图文件.dds"
  param:t="camo_skin_tex"
}
```

规则：
- `from`：原模型（CDK 提取的）模块代码，**必须带通配符 `*`**，否则贴图不加载。
- `to`：指向**该 blk 所在目录（即 blk 文件同级目录，可能深层嵌套）**的本地贴图文件，**必须带扩展名**；文件名需与磁盘文件精确匹配。
- `param:t="camo_skin_tex"`：仅 `set_tex` 使用，固定写法，不可遗漏。
- blk 为纯数据文件，**不支持任何形式的注释**（如 `//`、`/* */`、`#` 等）；写入注释会导致解析失败、涂装不被读取。

## 5. replace_tex 与 set_tex 的选择

| 场景 | 推荐方式 |
|------|----------|
| 飞机 / 直升机（全部贴图） | 只用 `replace_tex` |
| 坦克 / 舰船 可缩放迷彩 | `replace_tex` 替换 `camo_*` 前缀 |
| 坦克 / 舰船 固定整图 + 保留贴花/做旧 | `set_tex` + `param:t="camo_skin_tex"` |
| 法线 `_n`、损伤 `_dmg`、附加件、座舱、尾焰 | 只用 `replace_tex` |

一句话：**除「坦克/舰船固定迷彩且要保留贴花」外，全部用 `replace_tex`。**

只能使用 `replace_tex` 的类别：
1. 所有载具的法线贴图 `_n` / `_n_dmg`；
2. 所有空中载具的全部贴图（含 `_a`、`_c`、法线、损伤等）；
3. 陆地载具的附加组件（侧网、机枪、枪架、爆反、工具箱等）；
4. 座舱玻璃、瞄准镜、尾焰、发动机火焰等特殊贴图。

## 6. from 模块代码语义

`from` 的模块代码来自 CDK 提取的原贴图文件名，命名有稳定规律，可拆为「**部件前缀 + 贴图类型后缀**」。

### 6.1 后缀（贴图类型）分类

| 后缀 | 含义 |
|------|------|
| `_c` | 载具主要贴图文件，即实际显示效果 |
| `_a` | 同上，一般用于低级空中载具 |
| `_c_dmg` | 受损状态下的主要贴图 |
| `_a_dmg` | 同上，一般用于空中载具 |
| `_n` | 法线贴图，控制表面光滑度、反光度、细小凹凸 |
| `_n_dmg` | 受损状态法线贴图 |
| `_ao` | 环境遮蔽（AO）贴图，模拟面间距离、边缘对照 |

### 6.2 部件前缀（贴图部位）分类

| 前缀 | 含义 |
|------|------|
| `body` | 车身 / 船身 |
| `turret` | 炮塔 |
| `gun` | 武器（主炮） |
| `mount` | 机枪支架 |
| `pylons` | 飞机武器挂架 |
| `track` | 坦克履带 |
| `at` | 附加网 / 板状零件 |
| `cockpit` | 座舱（框架/仪表盘/指针） |
| `camo` | 陆/海载具全局迷彩（覆盖在普通贴图上） |
| `Jet_flame` / `Jet_flame_diamonds` | 喷气尾焰（带/不带马赫环） |
| `rottex` | 螺旋桨转动效果配色 |
| `n_blade_slow` / `n_blade_fast_propmask` | 螺旋桨慢/快转动动画（黑白表透明） |
| `lifeboat` | 救生艇 |
| `flag_<国家>` | 海军小旗 |
| 武器名（`tt-`鱼雷 / `mg-`机枪 / `flak-`高射炮） | 对应武器型号贴图（海军居多） |

- 通用件/武器**无载具前缀**，如 `us_aim_9l_sidewinder`、`lau_7`、`us_610gal_drop_tank`，因此可在不同机型 blk 间复用同一 dds。
- 机体专属贴图带载具前缀，如 `f_15a_c*`、`vt_5_body_c*`。

> ⚠️ 注意：以上模块代码命名规律是**社区经验总结，并非官方规范**。Gaijin 在开发不同载具时命名并不统一，实际 `from` 代码可能出现无前缀、后缀变体、拼写各异等情况。因此程序解析时**不能依赖固定的前缀/后缀做硬性判定**，应以 blk 中实际书写的值为准；本表仅作人工阅读与分类的参考。

## 7. to 贴图文件

- 指向**该 blk 文件所在目录（同级目录，可能深层嵌套）**的本地文件，必须带扩展名，通常需与磁盘文件精确同名（含大小写，见 §9）。
- 贴图格式：
  - **DDS**（DirectDraw Surface，DXTC 压缩，NVIDIA 开发）：适合涂装制作。
    - `DXT5 (RGBA)`：最常用，8K 约 64MB→2MB，压缩率高、色差小。
    - `8.8.8.8`：几乎不压缩，极高质量/反光，但显存带宽压力大、易掉帧。
    - 可关闭/调整 Mipmap（一般 lv 0~1），大角度更锐利、色差更小。
  - **TGA**：PS 无需插件即可读写、保存快，用作快速预览；默认强制 Mipmap 导致大角度模糊、有色差，一般不作最终成品。

## 8. Alpha 通道规则（仅对 `_c` 贴图有效）

| 命令 | Alpha 白 | Alpha 黑 |
|------|----------|----------|
| `set_tex` | 全局迷彩透明 | 全局迷彩不透明 |
| `replace_tex` | 不透明 | 透明 |

- 其他贴图（`_n`、`_a` 等）的 Alpha 含义因车型而异，不可套用。
- 背景：`set_tex` 存在是因为地面载具的 `_c` Alpha 蒙版对应"载具保养/磨损状态"，而旋转缩放的主语是全局迷彩（`camo`）。

## 9. 常见错误与游戏崩溃

书写/文件错误会导致：轻则涂装不被读取，重则游戏直接崩溃。

| 错误 | 后果 |
|------|------|
| `from` 没加 `*` | 贴图不加载 |
| `to` 漏写扩展名 | 不显示 |
| 文件名大小写 / 国家前缀错误 | 不匹配（Windows 大小写不敏感能跑，跨平台会炸） |
| blk 引用了载具没有的模块 | 应删除对应行 |
| 飞机误用 `set_tex` 或 `camo_skin_tex` | 无效 |
| 法线用 `set_tex` | 无效或报错 |
| `set_tex` 漏写 `param:t="camo_skin_tex"` | 书写错误（崩溃/不读） |
| `replace_tex` 多写 `param` | 书写错误 |
| 8.8.8.8 / 过高分辨率 | 加载压力过大导致崩溃 |
| blk 中含注释（`//`、`/* */`、`#` 等） | 解析错误 / 不被读取 |

## 10. 管理器可做的静态校验（由错误清单推导）

皮肤管理器应在加载模组时自动检查以下项，并汇总报告：

1. **通配符**：`from` 是否含 `*`；缺失则警告。
2. **扩展名**：`to` 是否以 `.dds` / `.tga` 结尾；缺失则警告。
3. **文件存在性**：`to` 引用的贴图是否在该 **blk 所在目录（同级目录）** 内存在；缺失则贴图丢失。
4. **大小写精确匹配**：建议大小写敏感校验（Windows 下不敏感能跑，但脆弱）。
5. **命令/参数合法性**：`set_tex` 必须有 `param`，`replace_tex` 不能有 `param`；`set_tex`/`camo` 不应出现在空中载具 blk 中；`_n` 必须用 `replace_tex`。
6. **加载压力提示**：读取 dds 头，提示超高分辨率 / `8.8.8.8` 格式风险。

### 实际示例数据中发现的问题（验证用）

- `[F-15-NEWJERSEY]/f_15a.blk` 引用了 `a_1.dds`、`aim9l.dds`、`n_n.dds`、`pit.dds`，但**该 blk 同级目录**内不存在 → **缺失贴图**（校验项 3 命中）。
- `[F-15-SHINANO]/f_15a.blk` 写 `lau_7_c.dds`，实际文件为 `Lau7.dds` → **大小写不一致**（校验项 4 命中）。
