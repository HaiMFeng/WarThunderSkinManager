## 分级与书写规则

### 严重程度（Severity）

按**影响面**与**可绕过性**定级，等级号沿用业界通行的 Severity 四级（S1–S4）：

| 等级 | 名称 | 判定标准 |
| :--: | --- | --- |
| **S1** | 致命 Critical | 核心功能不可用、用户数据损坏或丢失、崩溃且无法绕过 |
| **S2** | 严重 High | 主要功能受损，或结果错误且没有合理的绕过手段 |
| **S3** | 一般 Medium | 次要功能异常或体验明显受损，存在可接受的绕过手段 |
| **S4** | 轻微 Low | 不影响功能：文案、性能、界面细节、代码结构等长期欠账 |

两条纪律：

- 严重程度描述问题**有多严重**，不等于修复先后。判不准时取**更低**等级，不夸大。
- 只用这四档，不新增加中间档（如 S2.5）；确有需要时用文字补充说明，保持等级之间可比。

### 书写格式

每条问题一个三级标题，标题为「编号 + 一句话结论」，字段固定、顺序固定：

```markdown
### KI-001 一句话说明问题与影响

- **严重程度**：S3（一般）
- **状态**：未修复 / 处理中
- **表现**：现象、触发条件、影响面
- **绕过**：用户可用的临时手段，没有就写「无」
- **思路**：计划怎么改；尚未想清时写「待评估」
```

编号 = `KI-` + 三位递增序号，一经分配不再复用，也不因排序调整而改号。

### 排列与归类

**不按「功能缺陷 / 代码结构 / 体验」等类别分节**：所有问题排在同一个清单里，按严重程度从高到低排列（同级按编号先后）。避免同一问题被归错类别、或在多处重复维护。

- **严重程度**：S4（轻微）
- **状态**：未修复
- **表现**：7 个文件超过 500 行，其中 3 个接近 1900 行——`ViewModels/SkinsViewModel.cs`（1895）、`ViewModels/MainViewModel.cs`（1893）、`Dev/SelfTest.cs`（1887）；其余为 `ViewModels/PackageEditorViewModel.cs`（664）、`Services/Online/AppUpdateService.cs`（616）、`Services/Packages/ImportService.cs`（533）、`ViewModels/VehiclesViewModel.cs`（522）。阅读与定位成本高，改动时 diff 噪音大、易冲突。
