## 代码结构

以下为代码组织上的已知欠账，**不影响功能与使用**。

### 单文件体积过大

几个类已长到单文件数百至近两千行，阅读与定位成本高，改动时 diff 噪音大、易冲突。目前超过 500 行的文件：

| 文件 | 行数 |
| --- | ---: |
| `ViewModels/SkinsViewModel.cs` | 1895 |
| `ViewModels/MainViewModel.cs` | 1893 |
| `Dev/SelfTest.cs` | 1887 |
| `ViewModels/PackageEditorViewModel.cs` | 664 |
| `Services/Online/AppUpdateService.cs` | 616 |
| `Services/Packages/ImportService.cs` | 533 |
| `ViewModels/VehiclesViewModel.cs` | 522 |

前三个是重点（近 1900 行）。拆分按「行为不变的小步重构」推进：先确认自检覆盖了要动的代码路径，再按职责（加载 / 筛选 / 排序 / 命令等）抽成 `partial` 分部或协作类，每步跑一次构建与自检，保持 0 error / 0 warning、自检异常 0。

⚠️ `Dev/SelfTest.cs` 的体量可能是**刻意**的——自检清单需要一览无余。拆它之前先确认发布自检脚本对它的约定，不要为了整齐削弱自检自身的可读性。
