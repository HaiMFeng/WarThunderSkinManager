> **性质**：**设计稿，尚未实施**。本文固定"从便携散文件改为**安装器渠道**"与"**应用内自更新**"的

>
> 决策时间：2026-10-08。已定事项见 §2。

## 1. 为什么要改渠道

现状是"**便携单文件 exe + 用户随手放**"（`package-release.ps1:50-62`：`--self-contained` +
`PublishSingleFile`，产物 `WarThunderSkinManager-<版本>-win-x64.exe` / `.zip`）。它有三个与"更新"直接冲突的性质：

| 现状事实 | 证据 | 造成的问题 |
|---|---|---|
| 程序**没有稳定的安装位置与名字**，用户可任意改名/移动 | 产物是散文件，无安装器 | 更新找不到"该替换谁"；用户从旧副本/旧快捷方式启动就永远停在旧版 |
| 程序**从不往 exe 所在目录写任何东西** | 全仓 `AppContext.BaseDirectory` 0 引用 | ——（这是优点，见下） |
| 用户可能同时存在多份副本 | 内测期"下载夹一份、桌面一份"很常见 | 单实例 Mutex（`Local\WarThunderSkinManager.SingleInstance`，`App.xaml.cs:13-14,87-98`）会挡住另一份，用户更困惑 |

**关键判断**：问题的本质不是"替换文件难"，而是**缺少"安装身份"**。所以引入安装器（而不是继续加固便携版的
就地替换逻辑）——有了安装器，"替换文件"这件事由安装器在程序退出后做，**我们不必写最脆弱的那段代码**
（自锁定、两次 rename、`.bak` 回退、断电自愈全部不需要）。

同时保留一个天然兜底：因为程序不写自身目录，**安装目录里的 exe 拷走就是便携版**——zip 因此仍会上传（见 §2）。

## 2. 已定决策（本次敲定，不再讨论）

| # | 决策 | 说明 / 理由 |
|---|---|---|
| 1 | **安装器用 Inno Setup** | 成熟、脚本化（一个 `.iss`）、支持静默安装与同目录覆盖升级；"自安装"方案要自己扛快捷方式（COM）、注册表、自删除，收益不足 |
| 2 | **zip 仍上传，但文档只推广安装器** | 退路成本为零（脚本本来就有 zip 产物）；用于 U 盘/无权限机器，或安装器被 SmartScreen/杀软拦下时 |
| 3 | **默认每用户安装到 `%LOCALAPPDATA%\Programs\WarThunderSkinManager`**，允许用户改目录（引导不要选 `Program Files`） | 每用户安装**不需要 UAC**（静默更新才不会弹提权框）；装到 `Program Files` 会让静默更新需要提权 → 容易失败 |
| 4 | **回滚只给"旧版本下载页"链接**（不做自动回滚、不保留旧安装包） | 复用现有 `ReleasesUrl` + `OpenLinkCommand`（`MainViewModel.cs:119-125`）即可；GitHub Releases 页历史版本都在（含 zip 与 Setup） |
| 5 | **现有内测用户手工迁移**（清除旧散文件、改用安装器） | 用户少且都认识；迁移步骤写进本版发布说明（§8） |

**明确不做**（边界，见 §13）：增量/差分更新、自动回滚与静默装旧包、便携版就地替换（`.bak`/apply 模式）、
内测期代码签名、per-machine（全域）安装。

## 3. 已核实的外部与内部事实（实施依据）

### 3.1 GitHub Releases（实测 `api.github.com`，2026-10-08）

- 共 **5 个 release**（`v0.1.0-beta` … `v0.1.4-dev`），**全部 `prerelease=false`、`draft=false`**。
- 附件命名稳定：`WarThunderSkinManager-<版本>-win-x64.exe`（≈67.2 MB）/ `.zip`（≈61.6 MB）。
- **每个附件都带 `digest` 字段**，格式 `sha256:<64 位十六进制>`（9/9 全有）。例：
  `v0.1.4-dev` 的 zip → `sha256:6442d3853d0dfe4a7c400c531f79fafeb85b0bb7766193e1407c4d2a8c612f75`，`size=61647974`。
- `v0.1.0-beta` **只有 zip、没有 exe** → 资产选择必须容错。
- `content_type` 不一致（`application/x-zip-compressed` vs `application/zip`）→ **不要按 content_type 选**，按文件名。
- 发布说明（`body`）是中文 Markdown，含「从旧版本升级」章节 → 卡片里可直接展示。

### 3.2 程序内部可复用的既有能力

| 能力 | 位置 | 本功能怎么用 |
|---|---|---|
| 版本号 | `AppInfo.Version`（`AppInfo.cs:17-20`，`v0.1.4-dev`，已剥 `+短哈希`） | 与远端 tag 比较 |
| 单实例 Mutex | `Local\WarThunderSkinManager.SingleInstance`（`App.xaml.cs:13-14,87-98`） | 同时作为 Inno 的 `AppMutex`，安装器能等到程序退出 |
| 重启程序 | `MainViewModel.Restart()`（`MainViewModel.cs:963-979`） | "重启并安装"的写法模板 |

| 关闭拦截（有先例） | `MainWindow.xaml.cs:46-68`（下载中确认） | 更新安装阶段禁止退出，照抄该规则 |
| 全局处理中遮罩 | `Services/BusyIndicator.cs`（本次会话新增） | 下载/安装阶段统一反馈，并天然挡住连点 |
| HTTP 客户端范式 | `ResourceUpdateService.cs:59-66`（静态 `HttpClient` + `User-Agent`） | 新服务沿用（各自 UA 后缀，便于溯源） |
| Releases 页链接与打开命令 | `MainViewModel.cs:119-125`（`ReleasesUrl` / `OpenLinkCommand`） | 决策 4 的"旧版本下载页"直接用现成的 |
| 原子写文件 | `AtomicFile.WriteAllText/WriteAllBytes` | 写更新状态文件 |
| 配置目录 | `ConfigService.DefaultConfigDirectory()` = `%LOCALAPPDATA%\WarThunderSkinManager`（`ConfigService.cs:12-16`） | **更新状态与下载暂存**放这里；**安装器绝不碰这里** |

### 3.3 三个目录的分离（硬约束）

| 目录 | 内容 | 安装器/更新的权限 |
|---|---|---|
| **安装目录**（`%LOCALAPPDATA%\Programs\WarThunderSkinManager`） | `WarThunderSkinManager.exe`（+ 卸载器） | **可读写**（安装器只管这里） |
| **配置目录**（`%LOCALAPPDATA%\WarThunderSkinManager`） | `config.json`、`lang/`、`ref/`、`mappings/`、`index/`、`previews/`、字体提取、`update-state.json`（新增） | **只读/只写自己的状态**，安装与卸载**都不动**用户数据（卸载默认保留） |
| **资源目录 / UserSkins**（用户自选） | `packages/`、`blobs/`、`imports/`、`WTSM/` 输出 | **完全不碰** |

## 4. 安装形态

### 4.1 目录布局

```
%LOCALAPPDATA%\Programs\WarThunderSkinManager\        ← 安装根（Inno {app}）
    WarThunderSkinManager.exe                         ← 唯一槽位名（固定，不随版本变）
    unins000.exe / unins000.dat                       ← Inno 卸载器与元数据
    （如需图标：略——程序自带 ApplicationIcon，无需快捷方式图标文件）

%LOCALAPPDATA%\WarThunderSkinManager\                 ← 配置目录（与安装根**并列**，不是子目录）
    config.json  lang\  ref\  mappings\  index\  previews\
    update-state.json                                 ← 本功能新增（见 §6.4）
    updates\                                          ← 下载暂存（安装成功后删除）
```

**为什么不用"版本目录 + current.txt 指针"**：那套是为"没有安装器"设计的（回退=改指针）。有安装器后，
Inno 的固定 `AppId` 就能做到"同目录覆盖升级"，槽位名固定 → 升级天然原子性由安装器负责，我们也少写一套布局与启动器。

### 4.2 安装 / 升级 / 卸载

| 动作 | 行为 |
|---|---|
| 首次安装 | 用户运行 `WarThunderSkinManager-Setup-<版本>-win-x64.exe` → 选目录（默认每用户路径）→ 解出 payload → 建快捷方式 → 写卸载项（`HKCU\...\Uninstall\{AppId}_is1`，含 `InstallLocation` / `DisplayVersion`） |
| **升级**（安装器渠道） | 再跑一次新版 Setup：固定 `AppId` → **同目录覆盖**、快捷方式与卸载项更新；**不碰配置/资源目录** |
| **应用内自更新** | 下载 Setup → 校验 → 静默运行 → 启动新版本（§6） |
| 卸载 | Inno 卸载器删安装目录与快捷方式、删卸载项；**默认保留**配置目录与用户数据（向导里提供"同时删除配置与预览缓存"的**可选**勾选，默认不勾） |

### 4.3 "我是不是安装版" 的自检（应用侧）

启动时读 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\{AppId}_is1`：

- 读到 `InstallLocation` 且与 `Environment.ProcessPath` 所在目录一致 → **安装版**，自动更新可用；
- 不一致（如用户拷走 exe 单独运行、或从旧副本启动）→ **便携运行**：卡片显示"当前不是安装版，无法自动更新"，
  并给两个动作：「下载安装器」（打开 Releases 页）+ 提示"安装版才能自动更新"；
- 读不到键（从未安装）→ 同上。

> 这也顺带解决"用户拿老快捷方式启动旧副本"的问题：旧副本自己会提示"请改用安装版"，
> 且**不会**去更新一个不是它的槽位。

## 5. 安装器（Inno Setup）职责清单

单文件脚本 `installer/WarThunderSkinManager.iss`（随仓库维护，产物在发布流程里生成）。

| 区块 / 指令 | 取值 | 理由 |
|---|---|---|
| `AppId` | 固定 GUID（**一旦确定永不改**） | 决定"同目录覆盖升级"与卸载项的稳定身份 |
| `AppName` / `AppVersion` / `AppVerName` | `WarThunder Skin Manager` / `<版本>` / 含版本 | 控制面板显示、升级判定 |
| `DefaultDirName` | `{localappdata}\Programs\WarThunderSkinManager` | 每用户、无 UAC（决策 3） |
| `PrivilegesRequired` | `lowest` | 默认不提权 |
| `PrivilegesRequiredOverridesAllowed` | `dialog` | 用户仍可自选需要提权的目录（会 UAC）；**文档引导不要这么选** |
| `AppMutex` | `Local\WarThunderSkinManager.SingleInstance` | 安装器据此**等待/关闭**正在运行的程序（与程序单实例同一个名字，天然一致） |
| `CloseApplications` / `RestartApplications` | `yes` / `yes` | 用 Restart Manager 等我们的进程退出再替换文件（**静默更新可靠的关键**） |
| `Compression` | `lzma2/ultra64` + `SolidCompression=yes` | payload 已是压缩过的单 exe，别指望变小（见 §5.2） |
| `SetupIconFile` | `Assets\app.ico` | 观感一致 |
| `UninstallDisplayName` / `UninstallDisplayIcon` | 带版本名 / `{app}\WarThunderSkinManager.exe` | 控制面板可读 |
| `WizardStyle` / `DisableDirPage` | `modern` / `no` | 允许改目录（决策 3） |
| `[Files]` | `WarThunderSkinManager.exe`（payload） | 来源 = `dotnet publish` 的单文件产物 |
| `[Tasks]` | `desktopicon`（**默认不勾**） | 开始菜单必建；桌面可选（行业惯例） |
| `[Icons]` | 开始菜单 +（勾选则）桌面 | 快捷方式由安装器管理 = 不再依赖用户的临时 `.lnk` |
| `[Run]` | ① `Check: WizardSilent` → 装完**自动启动**程序；② `Check: not WizardSilent` → 给"运行程序"勾选（默认勾） | 静默更新后要自动回到界面；交互安装保留标准体验 |
| `[UninstallDelete]` | 只删 `{app}` 内我们放的文件 | **绝不**删配置目录与用户数据 |
| 语言 | `ChineseSimplified.isl`（+ 可选英文） | 界面一致 |

### 5.1 静默安装参数（更新流程用）

```
Setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /LOG="<配置目录>\updates\install.log"
```

- `/NORESTART`：**不允许**安装器自行重启（若它判定"文件被占用，需重启后替换"，我们要把它当**失败**处理并提示手动下载安装，而不是悄悄留个半装状态）。
- 顺序：**先让程序自己退出**（取消后台任务、写完 `update-state.json`、`Shutdown()`），由 Restart Manager 保证文件可替换。

### 5.2 体积预期（不要有错误期待）

payload 是 `EnableCompressionInSingleFile=true` 压过的单 exe（≈67 MB），Inno 再套一层 LZMA2 基本压不动 →
Setup ≈ **66–68 MB**，与现有 zip（≈62 MB）同量级。**"只发安装器会变小"是不成立的**。

## 6. 更新流程

### 6.1 时序

| # | 执行者 | 动作 | 失败/中断处理 |
|---|---|---|---|
| 1 | 应用（启动后延迟 30–60 s，24 h 内至多一次，手动「检查更新」随时可点） | `GET /repos/HaiMFeng/WarThunderSkinManager/releases?per_page=20`，带 `If-None-Match`（304 不计限流） | 网络失败 → **静默**（仅卡片显示"检查失败"，不打扰） |
| 2 | 应用 | 过滤：跳过 `draft`；按频道决定是否接受 `prerelease`（§6.2）→ 取版本最大者 → **资产选择**（§6.3） | 无可用资产 → 卡片给"手动下载"（打开 Releases 页） |
| 3 | 用户 | 点「更新」→ 前置检查：**空闲**（无导入/下载/重建）、安装目录**可写**（写探测文件）、磁盘剩余 ≥ 2× 安装包体积 | 不满足 → 明确提示（"有任务在进行/目录不可写"），不进入下载 |
| 4 | 应用 | 下载到 `<配置目录>\updates\<版本>.part`（1 MB 缓冲；进度 %、速度、剩余时间；可取消；停滞 30 s 掐断；最多 5 次重试；**Range 断点续传**） | 取消 → 保留 `.part` 供续传；失败 → 状态回"有新版本"+重试按钮 |
| 5 | 应用 | 校验：`size` 与 `sha256` 均须等于 API 的 `assets[].digest` | 不符 → 删文件，报"下载损坏，请重试"；**绝不继续** |
| 6 | 应用 | 写 `update-state.json`（`phase=pending-install`，记目标版本、安装包路径、sha256、时间），落盘完成态 | 写失败 → 中止，原版本不受影响 |
| 7 | 应用 | 用户确认「立即重启并安装」→ 收尾（`CleanupOnExit`）→ 拉起 `Setup.exe /VERYSILENT …`（detached）→ 自身退出 | 拉不起来 → 清状态，给"手动双击安装包"提示（并打开其所在目录） |
| 8 | 安装器 | Restart Manager 等我们退出 → 覆盖安装 → （静默模式下）启动新版本 | 判定"需重启后替换"或安装失败 → 见 §10 兜底 |
| 9 | 新版本首次启动 | 读 `update-state.json`：**健康确认**（配置加载成功、库快照可读或可重建、主窗口已显示）→ 清状态 → 一次性**非模态**提示"已更新到 vX · 查看更新内容"（可关、可「跳过此版本」） | 启动崩溃 → 状态保留（下次启动仍提示）；**不做自动回滚**（决策 4），提示里给"旧版本下载页" |

### 6.2 版本比较与频道

- **必须 SemVer 语义**：`0.1.10 > 0.1.9`（不能字符串比）；`-dev`/`-beta` 是**预发布标识**（`0.1.5-dev < 0.1.5`）。
  tag 带 `v` 前缀 → 解析时剥掉；忽略 `+build` 元数据。
- **不用 `releases/latest`**：`latest` 会跳过 prerelease，一旦以后把 `-dev` 正确标成 prerelease 就会"永远检查不到更新"。
  改为拉列表 + 自己过滤。
- **频道**：
  - 内测期（当前）：**接受预发布**（等价于"所有非 draft 的 release 都算候选"）；
  - 正式期：只接受 `prerelease=false`，并在设置里提供「接收测试版」开关。
  - 发布侧配合：`-dev` / `-beta` 的 release 建议加 `--prerelease`（`wtsm-release` 技能同步改），语义与代码一致。

### 6.3 资产选择规则

1. 候选附件名必须匹配：`WarThunderSkinManager-Setup-<版本>-win-x64.exe`（前缀 + 含 `-<版本>-` + `-win-x64.exe` 结尾）；
2. 缺失 Setup → 卡片只给"手动下载"（不自动降级去装 zip：解压散文件会重新引入"没有安装身份"的问题）；
3. `content_type` 不可信（实测不一致），**只按文件名**判断；
4. `digest` 缺失 → **拒绝自动更新**（fail closed），改为手动下载。

### 6.4 状态文件 `<配置目录>\update-state.json`

```jsonc
{
  "phase": "idle | pending-install | installed",   // installed = 已安装、待首次启动提示
  "targetVersion": "0.1.5-dev",
  "installerPath": "…\\updates\\0.1.5-dev.exe",
  "sha256": "…",
  "downloadedAt": "2026-10-08T12:00:00+08:00",
  "notifiedVersion": "0.1.4-dev",                  // 上次已提示过的版本（避免反复提示）
  "skippedVersion": ""                             // 「跳过此版本」
}
```

写入用 `AtomicFile`；**放配置目录**（安装器不碰它；目录迁移时随之带走 ✓）。

## 7. 界面：设置页「更新应用」卡片

### 7.1 位置与骨架

- 位置：**「更新资源」卡上方**（应用版本 > 数据表版本），同属左侧滚动区内（`Views/SettingsView.xaml`，卡片统一骨架
  `Border Style="{StaticResource Card}"` + `SectionTitle` + `PageSubtitle`）。
- 文案：两张卡要用不同词区分——本卡是"**程序版本**"，另一张是"**数据表版本**"。语言键前缀 `settings.appUpdate.*`。

### 7.2 状态机（卡片唯一事实来源）

| 状态 | 卡片内容 | 可用动作 |
|---|---|---|
| 未检查 | "尚未检查更新" | 检查更新 |
| 检查中 | 加载圈 + "正在检查更新…" | （禁用） |
| 已是最新 | "已是最新（v0.1.4-dev）· 上次检查 2 小时前" | 检查更新 |
| **有新版本** | 版本号 + 发布日期 + 安装包体积 + **发布说明前若干行**（纯文本）+「查看完整说明」（打开 release 页） | **更新** / 稍后 / **跳过此版本** |
| 下载中 | 进度条 + 百分比 + 速度 + 剩余 + 取消 | 取消 |
| 已下载待安装 | "已就绪，重启后安装" | **立即重启并安装** / 稍后 |
| 安装失败 | 原因 + 重试 / **手动下载** | 同上 |
| 已跳过此版本 | "已跳过 vX（可撤销）" | 撤销跳过 / 检查更新 |
| 非安装版 | "当前不是安装版，无法自动更新" | 下载安装器 / 打开旧版本下载页 |
| 检查失败（网络） | "检查失败（可稍后重试）" | 重试 / 手动下载 |

- 语言键（新增，按既有 `settings.resource.*` 风格）：`settings.appUpdate`、`.hint`、`.check`、`.checking`、`.notChecked`、
  `.upToDate`、`.hasUpdate`、`.update`、`.downloading`、`.verifying`、`.ready`、`.installNow`、`.later`、`.skip`、
  `.skipped`、`.failed`、`.failNetwork`、`.failTimeout`、`.failChecksum`、`.manual`、`.releaseNotes`、`.oldVersions`、
  `.notInstalled`、`.updatedNotice`、`.notEnoughSpace`、`.busy`、`.notWritable`。
- **可选（推荐）**：左侧导航"设置"项在"有新版本 / 待安装"时显示一个小圆点（不弹窗、不打断）。

### 7.3 交互闸门（"锁死其他操作"的完整口径）

1. **遮罩 + 挡住交互**：下载/安装阶段一律用 `BusyIndicator`（文案「正在下载更新…」/「正在安装更新…」），
   从根上杜绝连点；
2. **禁止退出**：`MainWindow.OnWindowClosing` 增加一条——安装阶段（已拉起 Setup 之前的那一小段）确认退出
   （照抄现有"WT Live 下载中"的写法，`MainWindow.xaml.cs:46-68`）；
3. **要求空闲**：开始更新前检查是否有导入/下载/资源库重建在进行，有则提示"请等待当前操作完成"；
4. **全局维护闸门**：`MainViewModel` 加 `IsMaintenance`（更新进行中为真）——设置页的「更新资源 / 全量重建 /
   存储维护 / 清除数据」等按钮 `IsEnabled` 绑定取反，命令内也 early return（双保险）；
5. **前置预检**：安装目录可写探测 + 磁盘空间（≥ 2× 安装包体积）；
6. **禁止并发更新**：同一时刻只允许一个更新流程（`Interlocked` 标志，与「全量重建」同款）。

## 8. 迁移（现有内测用户）

发布说明里给出**固定步骤**（用户少、都认识，一条消息 + 文档留痕即可）：

1. 退出正在运行的旧版（若有下载在进行，先取消）；
2. 运行 `WarThunderSkinManager-Setup-<版本>-win-x64.exe`，一路下一步（目录默认即可）；
3. 从**开始菜单**启动"WarThunder Skin Manager"，核对设置页「关于」里的版本号；
4. 删除旧的散 exe/zip 与旧快捷方式（**用户自己删**，程序不代劳）。

应用侧配合（不打扰但不放任）：

- 检测到"非安装版"→ 卡片提示"当前不是安装版，无法自动更新"（§4.3）；
- 若配置里记录的"上次运行路径"与当前不同（说明换过位置）→ 首次启动时一次性提示"已迁移到安装版，
  旧的副本可以删除了（打开所在目录）"——**只提示，绝不自动删用户文件**；
- 明确写进发布说明：**配置、涂装库、激活输出都不受影响**（安装器只写安装目录）。

## 10. 失败矩阵（兜底口径）

| 情形 | 表现 | 处理 |
|---|---|---|
| 网络不通 / GitHub 不可达（国内常见） | 检查或下载失败 | 检查**静默**；下载失败给"重试 / 手动下载（打开 Releases 页）"；`.part` 保留可续传 |
| 下载被截断 / 被中间层篡改 | sha256 不符 | 删文件、报"下载损坏"，重试（**绝不安装**） |
| SmartScreen / 杀软拦截安装器 | 安装器起不来或被杀 | 提示"手动双击安装包"（并打开其所在目录）+ 说明"更多信息 → 仍要运行" |
| 安装目录不可写（装在 Program Files / OneDrive 同步目录） | 预检失败或静默安装失败 | 预检即拦下并说明原因；静默失败 → 手动安装指引（UAC 场景） |
| 安装器判定"需重启后替换文件" | 本次未真正替换 | 视为失败：提示手动安装（**不允许**自动重启机器） |
| 磁盘空间不足 | 下载/安装失败 | 前置预检（≥ 2× 体积）后提示 |
| 更新后启动崩溃 | 状态未清 | 不强推自动回滚（决策 4）：下次启动仍提示更新结果 + 给"旧版本下载页"；用户可自行装回旧版 |
| 用户中途关掉安装器 | 版本未变 | 下次启动读状态发现 `pending-install` 仍未完成 → 卡片回到"有新版本"（可重试） |

## 11. 不变量与安全

1. **只碰安装目录**：安装/卸载/更新都不写配置目录与资源目录（除本功能自己的 `update-state.json` 与 `updates\` 暂存）。
2. **不信任任何未经校验的下载物**：只有 `size` + `sha256` 双校验通过后才允许执行；`digest` 缺失则拒绝自动更新。
3. **URL 白名单**：只接受 API 返回的 `browser_download_url`，且 host ∈ `github.com` / `objects.githubusercontent.com`、
   路径前缀为 `/HaiMFeng/WarThunderSkinManager/releases/download/`。
4. **展示即文本**：release `body` 按纯文本渲染（裁剪长度、去控制字符、链接用系统浏览器打开），不解析 HTML/脚本。
5. **卸载默认不删数据**；删除配置需用户在卸载向导里显式勾选。
6. **安装身份自检**（§4.3）保证"更新作用在规范槽位"，不更新用户拷走的副本。

## 12. 可测性

### 12.1 离线自检（`Dev/SelfTest.cs` 新增断言，随 `build-and-selftest.ps1` 跑）

| 断言 | 要点 |
|---|---|
| 版本比较 | `0.1.10 > 0.1.9`；`0.1.5-dev < 0.1.5`；`v` 前缀与 `+build` 处理；相等判定 |
| Release JSON 解析 | 内嵌 fixture（含"只有 zip 的 `v0.1.0-beta`"形状）→ 版本、prerelease、assets（名/大小/digest）全解析 |
| 资产选择 | 正常选到 Setup；缺 Setup → 返回"需手动"；`content_type` 不同不影响；`digest` 缺失 → 拒绝 |
| 频道过滤 | 内测模式接受 prerelease；正式模式跳过 |
| 校验 | 正确 sha256 通过；改一字节必须失败；大小不符必须失败 |
| 静默参数拼装 | 产物字符串包含 `/VERYSILENT`、`/SUPPRESSMSGBOXES`、`/NORESTART`、`/LOG` |
| 状态机 | `idle → pending-install → installed`；`skippedVersion` 生效；`notifiedVersion` 只提示一次 |
| 身份自检 | 非安装目录 → 判定为"便携运行"、自动更新不可用 |
| 前置检查 | 空间不足 / 目录不可写 → 拒绝并给出对应文案键 |

> 网络、安装器与"替换自身"无法离线验证 → 走下面的真机清单。

### 12.2 真机手动验收清单

1. **首次安装**：干净机器（或删掉旧版）→ 运行 Setup → 开始菜单能启动、控制面板有卸载项、版本号正确；
2. **覆盖升级**：装旧版 → 再跑新版 Setup → 同目录被覆盖、快捷方式仍有效、**配置与涂装库未受影响**；
3. **静默自更新**：旧版里点「更新」→ 进度 → 静默安装 → 自动回到新版界面 → 首次启动提示出现一次；
4. **中断与失败**：下载中拔网 → 可续传/可重试；把安装包改一字节 → 校验失败且**不安装**；
5. **占用场景**：更新时程序正在下载 WT Live 涂装 → 应被前置检查拦下（"请等待当前操作完成"）；
6. **迁移**：从旧便携 exe 启动 → 卡片显示"不是安装版" → 按 §8 步骤装完后一切正常；
7. **卸载**：卸载 → 安装目录与快捷方式消失、**配置与资源目录保留**；
8. **降级**：从新版装回旧版 Setup → 能正常启动（数据兼容，若索引格式变过则首启重建快照）。

## 13. 明确不做（边界）

- **不做**增量/差分更新（内测人少，67 MB 可接受）；
- **不做**自动回滚、不保留旧安装包（决策 4：只给"旧版本下载页"）；
- **不做**便携版就地替换（`.bak` / `apply` 模式 / 两次 rename）——安装器存在后这套不再必要；
- **不做**代码签名（内测期；对外前必须补，见 §10 的 SmartScreen 兜底）；
- **不做** per-machine（全域）安装；
- **不做**"自动静默升级"（v1 一律用户确认后再装；自动检查只提示）。
