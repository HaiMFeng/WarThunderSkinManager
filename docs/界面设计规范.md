# 界面设计规范（WarThunderSkinManager）

> 配套功能设计见 `docs/软件功能设计.md`。本文档规定程序界面的视觉语言、设计令牌与组件规范，不含业务代码。
> **本文档为 2.0 版**：按现代设计系统（Design Tokens + Fluent 风格）重写，取代早期简版规范。

---

## 1. 设计原则

- **扁平（Flat）**：纯色块、清晰分隔、充足留白；不使用拟物、重描边与强渐变。
- **克制**：强调色（Primary）只用于**主操作**与**选中态**，避免满屏蓝。
- **一致**：颜色 / 圆角 / 尺寸 / 间距一律取自统一**设计令牌**，不写死魔数。
- **层次**：以「画布底 → 卡片 → 内容」三层表达层次，辅以极轻阴影，而非加粗边框。
- **动效节制**：短（≤ 300ms）、有明确意义；只用透明度 / 位移 / 颜色，不炫技。
- **文案外置**：界面文字不硬编码，全部来自语言文件（见 §7）。

### 2.6 图标

**一套字体**：**Font Awesome 7 Free Solid**（嵌入资源 `Assets/Fonts/fa-solid-900.otf`）。
许可：字体 SIL OFL 1.1、图标 CC BY 4.0——随包保留 `Assets/Fonts/LICENSE-FontAwesome.txt`。
全程序图标统一取自这一套（标题栏 / 导航 / 空态 / 对话框 / 缩略图占位），
**不再使用** Segoe MDL2 Assets 等系统图标字体，也不混用手绘几何或位图图标。

**引用机制（有坑，务必照办）**：嵌入字体的 `pack://…otf#族名`、`./Assets/Fonts/#族名` 等资源形式
**实测全部命中不到**（字体确实在程序集 `g.resources` 里；用一次性 WPF 探针把 7 种形式逐个验证过）。
实际可用的路径是：

1. `IconFontLoader.EnsureLoaded()` 把嵌入副本提取到 `%LOCALAPPDATA%\WarThunderSkinManager\`；
2. 用 **`file:///…/fa-solid-900.otf#Font Awesome 7 Free Solid`** 形式的 `FontFamily`
   （`IconFontLoader.IconFamily`）；
3. `App.OnStartup` 在**主题字典合并之前**注入 `Resources["IconFont"]`——XAML 侧照旧写
   `{StaticResource IconFont}`，无需感知上述细节。

注意 WPF 侧的**族名是 `Font Awesome 7 Free`**（"…Free Solid" 是 GDI+ 里的名字，只能出现在 file URI 的 fragment 上）。
`Themes/ThemeResources.xaml` 里**不要**再定义 `IconFont` 键（字典自己的键会盖住 App 资源里的那个）。
自检有断言守着：字体可解析 + 用到的 21 个字形缺失 = 0。

**字形（Unicode 私有区码位）**：

| 最大化 / 还原 | `F2D0` / `F2D2` | window-maximize / window-restore | 下载（列表入口） | `F063` | arrow-down |
| 关闭 | `F00D` | xmark | 缩略图占位 | `F03E` | image |
| 置顶 | `F08D` | thumbtack | 部件（空态） | `F12E` | puzzle-piece |
| 涂装管理 | `F1FC` | paintbrush | 信息 / 警告 | `F05A` / `F071` | circle-info / triangle-exclamation |
| 载具管理 | `F0FB` | jet-fighter | 错误 / 询问 | `F06A` / `F059` | circle-exclamation / circle-question |
| 多源复用 | `F24D` | clone | 密码锁 | `F023` | lock |
| 设置 | `F013` | gear | | | |

| 详情轮播上一张 / 下一张 | `F053` / `F054` | chevron-left / chevron-right | | | |

**「下载」这一个字形用在三处**：工具栏的下载列表入口、卡片右下角的下载按钮、列表空态插图 —— 三处必须是**同一个码位**，
否则同一页里会出现两种"下载"形状（原先工具栏是 `F0ED` `cloud-arrow-down` 的云朵、卡片是 `F019` `download` 的托线箭头，
笔画密度不同，14px 下云朵明显发糊、与 `F005` 星标 / `F021` 刷新不在一个密度上）。

**状态着色**：图标可以按**状态**换色，但只允许在主题画刷之间切换（四套主题自动一致）。
「WT Live 下载列表」按钮的图标是**三态互斥**：状态只有**一个来源** `SkinsViewModel.ButtonState`（枚举），
优先级 **失败 > 下载中 > 默认**，由静态纯函数 `SkinsViewModel.EvaluateButtonState` 算定：

| 状态 | 条件 | 视觉 |
|---|---|---|
| `Failed` | 存在 `State == Failed` 的项（**用户主动取消不算**） | `BrushDanger` **常亮红** |
| `Downloading` | 无未重试的失败项，且存在 `Downloading / Importing` 的项 | `BrushPrimary` + **呼吸**（`Opacity` 1 ↔ 0.3 脉冲，1.5 秒一个来回，`Forever`） |
| `Idle` | 全部完成 / 列表为空 / 只剩已取消项 | `BrushTextSecondary` |

- **失败优先**：同时有失败项与下载中的项时是**红色** —— 只要还有**没被重试**的失败项就保持红色；
  点「重试」把该项置回 `Downloading`，所以**所有失败项都被重试触发**之后才退出红色；
- 界面侧用两个互斥的 `DataTrigger` 绑 `ButtonState`；退出 `Downloading` 时 `ExitActions` 以
  `RemoveStoryboard` 移除呼吸动画（`Opacity` 回落到 1，不会卡在半透明）；
- 状态由 `SkinsViewModel` 在**列表增删**与**任一条目状态变化**时统一通知（`HookDownloadNotifications`）。
该入口在**涂装管理页页头**与 **WT Live 页工具栏**（最右）是**同一个控件** `Views/WtLiveDownloadsButton`：
悬停展开的下载列表浮窗、条目内的重试 / 取消语义都只有一份实现，两页不会走样；
「宿主隐藏时强制收起浮窗」（`Popup` 是 `StaysOpen=True`，视图隐藏不触发 `MouseLeave`）也由该控件自理。
该控件有**两种外观**（同一个控件、同一个浮窗，只换按钮的皮）：默认 = **次级按钮**
（涂装管理页页头，与相邻的「导入…」按钮同族）；`Borderless="True"` = **无边框图标按钮**
（透明底 + 无描边 + 高 34，**宽度随内容自适应**（`MinWidth=34` 兜底），WT Live 页工具栏用 ——
那里是「排序 / 搜索框 / 收藏的作者」这类图标按钮的语言）。
⚠️ 无边框变体的图标必须显式 `FontWeight="Normal"`：基底样式（`ButtonBase`）带 `SemiBold`，
而图标字体只有一个字重，继承到粗体会触发 WPF **合成加粗**，墨迹向右扩出、看着像"右侧被切"。
两页看到的是**同一份数据**（都绑 `SkinsViewModel.WtLiveDownloads`），在任一页操作，切到另一页看到的就是最新状态。

**浮窗条目的布局**（`ListPopup`）：一行四列 = 文件名（`*`，**先被压缩**）/
**状态文案**（`Auto` + `MaxWidth=150` + `TextTrimming=CharacterEllipsis` + `ToolTip` 给全文）/
重试 / 取消·移除。**状态列必须限宽** —— 它的内容含失败原因（异常消息），不限宽时 `Auto` 列会按
期望长度撑开、把右侧两个操作按钮**顶出浮窗**（实测踩过）。
相应地，**文案本身也要短**：操作指引（重试节奏、停滞超时）放按钮的 `ToolTip`，
长原因在 C# 侧折成一行并截断（`SkinsViewModel.Shorten`，默认 80 字）。

**处理中遮罩（长操作的统一反馈）**：任何**要等 1 秒以上**的操作（复制 / 删除 / 导入 / 迁移 / 重建资源库…）
都必须给出"处理中"反馈——否则用户看不到任何变化，会以为没反应而**连点**（重复触发同一个操作）。

- **唯一容器**：`Views/BusyOverlay`（全局唯一实例，宿主放在窗口最上层即可）。可见性由
  `Services/Infrastructure/BusyIndicator` 的引用计数驱动：`using var _ = BusyIndicator.Instance.Begin(Loc["busy.xxx"]);`
  **可嵌套**（内部计数），文案 / 进度 / 取消取**最外层**那次，计数归零才隐藏；
- 形态：半透明遮罩（主题背景色 + `Opacity=0.72`）+ 居中卡片
  （主题表面色 / 圆角 10 / 轻投影）+ **实心弧加载圈**（1.1 秒一圈，`Forever`）+ 一行文案（如"正在复制涂装包…"）；
  按需再加**进度条**（`Scope.Report`）与**取消按钮**（`Begin(text, onCancel)`）；
- **能力可组合**：不定态（只转圈）/ 确定态（再加进度条与 `已迁移 / 总量`、`N / M` 或百分比文案）/
  可取消（卡片内取消按钮）/ 仅文案（无加载圈，用于瞬时切换的短阶段，避免图标闪动）/ 全局独占（见下）；
- **作用域抑制**：`using var _ = BusyIndicator.Instance.Suppress();` —— 抑制期间**所有** `Begin`
  都返回空作用域：不显示遮罩、不改文案 / 进度，释放时也不误减别人的计数。用于"**静默**"流程：
  §5.7.3 的「一键导入」勾选后下载完直接解构，用户此刻还在看下载列表，全程不该出现全屏"处理中"。
  这里用**作用域**而不是逐个 `Begin` 调用点传参 —— 那条流程上遮罩来源分散（解构 / 收尾 /
  刷新方法内部的兜底），逐个判断曾漏掉一处（刷新那次），而抑制标志连**将来新增**的遮罩也一并盖住；
- **取消语义统一**：凡支持取消的操作，取消入口都在**遮罩上**（常驻可点），并可用 `Esc` 触发
  （`MainWindow.OnPreviewKeyDown` 闸门）；旧实现"关窗即取消"的做法已废弃；
- **加载圈是自绘的"实心弧圆环"**（样式下沉在 `Themes/ThemeResources.xaml` 的 `BusySpinner`，任何窗口可复用）：
  - `Ellipse` 描边走主题主色 + `StrokeDashArray` 只留约 300°——**单位 = 描边宽度的倍数**：
    尺寸 18 / 描边 2 → 中心线半径 `(18-2)/2 = 8`、周长 `2π×8 ≈ 50.27`、÷描边 `≈ 25.13`
    → `20.94 实 + 4.19 空`；加 `StrokeDashCap="Round"` 圆头、整体绕中心旋转；
  - **为什么不用图标字形**：图标字体的 `circle-notch`（`F110`）画出来是**一串短划**（"点串"观感）；
  - **为什么不做渐隐（彗尾）**：曾用 `OpacityMask` 线性渐变做过渐隐版本，**1× 真实尺寸下会让半圈
    看着像断掉**（与其余候选同屏渲染对比后否掉）——加载指示器首先要"一眼认出是在转"，
    因此取实心弧、只留一个干净缺口；
  - 尺寸与描边保持在 18 / 2：与遮罩卡片（`Padding=22,16`）搭配时 1× 下最清楚。
- **进度条同源**：统一走主题里的 `ProgressBar` 样式（与页内进度条同一份，四套主题自动一致）；
- **全局独占（禁用式）**：遮罩可见期间，宿主窗口的其余内容层与**此刻已存在的**其它顶层窗口一并
  `IsEnabled=false`，键盘焦点收到遮罩上——把"互斥"从编码纪律变成机制，封锁范围与模态窗等价。
  遮罩自身保持可交互，**取消入口始终可点**（长任务必须能在遮罩上取消）；
  **busy 期间新开的对话框不禁用**（如导入中途的压缩包密码框，必须可用）；
- **不做延时显示**：这些操作本来就要 1 秒以上，立即可见比"防闪烁"更重要；
- **busy 范围不得跨越模态窗**：进入 `Begin` 前要结束掉待交互的弹窗（如导入的预览确认），
  需要用户输入的对话框只能出现在两次 `Begin` 之间——否则它会被全局独占挡住（`IsEnabled=false`）而无法交互。

**顶部气泡提示（操作反馈的唯一出口）**：所有页面的"操作完成 / 失败"反馈都走这里，替代早期的
"标题栏一行文本"——后者有三个毛病：多条消息**互相覆盖**、一行宽度只能截断、12px 小字挂在角落**容易漏看**：

- **组件**：`Views/StatusToastsView`（挂在 `MainWindow` 根 Grid，`Panel.ZIndex=60` —— 在"处理中"遮罩（50）
  之上，所以遮罩期间的操作结果也看得见）+ `Services/Infrastructure/ToastService`（全局唯一队列）。
  位置**顶部居中**、纵向堆叠；顶部偏移 `44` = 标题栏 36 + 8 间隙，不遮窗口按钮；
  控件只占自身内容尺寸、**空白处不参与命中测试**（不挡底下界面）；
- **规则**（实现在服务侧，自检有断言）：最多同时 **4 条**，超出时**顶掉最早的一条**（先进先出）；
  每条默认展示 **3 秒**；**点击气泡任意位置**立即消除该条；
- **视觉**：圆角气泡（`BrushSurface` + `BrushBorder` + 轻投影），文案**换行**显示（不再截断）；
  底部贴边一条 2px 的**进度条**（主色，`ScaleX` 从 `0` 长到 `1`、走满 3 秒）；`Cursor=Hand` +
  `ToolTip=common.dismissHint` 提示"可点"；
- **动画**：**进入** = 淡入 + 自上而下落定 8px（180 / 220ms，`CubicEase EaseOut`），
  由 `EventTrigger.Loaded` 驱动；**退出** = 淡出 + 微微上移 6px（150ms），
  **由 code-behind 直接驱动**（`StatusToastsView.OnToastPropertyChanged`）——
  模板触发器里"由**属性变化**驱动"的 `DataTrigger.EnterActions` **实测不生效**
  （`EventTrigger.Loaded` 那种"元素自身事件"才正常），所以这两半各用各的机制。
  进入的初始态（`Opacity=0` / `Y=-8`）写在 XAML 上，免得"先实心闪一帧再淡入"。
  退出的**时机**：点击消除或到期时服务先把该条标记为 `IsDismissing`，
  再过 `ToastService.ExitGrace`（170ms，略长于 150ms 的动画）才真正出队 ——
  "点了就消失"的即时感与"有一个淡出过程"因此同时成立；
- **进度条不占气泡高度**：它与文案是**同一个 `Grid` 里的叠放子元素**（`VerticalAlignment=Bottom`），
  而不是 `StackPanel` 的第二个兄弟 —— 所以它贴在内底边上，却不参与高度计算；
  `Border` **不设 `Padding`**（内边距由文案自己的 `Margin` 撑），进度条才能直接顶到内边框；
  它 `Margin=0` **满宽铺到内边框**，两端再由气泡的**圆角裁剪**收进轮廓里 ——
  否则看着像"浮"在圆角外面；
- **文案用"上大下小"的内边距**（`Margin="16,11,16,9"`）：中文行框**底部**留的空白（descent）
  比顶部多 ~1.5px，等距内边距会让墨迹看着**偏上**，上边距多 2px 正好抵消。
  （踩过两次：先写成「上 10 / 下 12」—— 方向反了，越修越偏上；再改成上下等距 ——
  只去掉了自己引入的那部分，字体自带的那 1.5px 仍在。进度条是**叠放层**，本就不需要预留空间。）
- **圆角裁剪**：气泡 `Border` 上挂一个随尺寸更新的 `RectangleGeometry`（半径 10，与 `CornerRadius` 一致），
  由 code-behind 在容器生成后挂（`StatusToastsView.HookRoundedClip`）——
  WPF 没有内建的圆角 `Clip`。它作用在 `Border` 自身：`Clip` 在 `Effect` **之前**生效，
  所以投影不受影响（阴影沿裁剪后的圆角轮廓投）；
- **性能**：进度条动画是视图侧的 WPF `Storyboard`（跑在**合成线程**，不占 UI 线程），
  时长取 `ToastService.DefaultLifetimeDuration`（`x:Static` —— 动画属性上的绑定依赖 DataContext
  继承链、在模板里容易失效，所以不走绑定）；服务侧只用**一个** 100ms 的低频定时器做到期回收，
  因此并发开销是**常数级**、与条数无关（上限本就 4 条）；
- **调用方式**：各 ViewModel 内部沿用私有 `ShowStatus(msg)`，实现只有一行
  `ToastService.Instance.Show(msg)` —— 调用点不必感知队列；
- 早期的"连续相同消息 → 标题栏光晕脉冲"代偿机制**一并删除**：相同文案现在各自成条，无需脉冲提神。

**例外：页内持续反馈不并入遮罩**——以下三处是**非阻断 / 多任务 / 局部**反馈，塞进全屏遮罩是**退化**而非统一：

- 应用更新下载：持续数分钟，用户应在下载期间继续使用程序（卡片自带进度 + 速度 + 取消；更新期间的并发
  由 `IsMaintenance` / `HeavyActionsEnabled` 闸门挡住，不靠遮罩）；
- WT Live 下载列表：**多任务可并行**，遮罩会挡住列表本身与各行的重试 / 取消；
- 部件表加载：页面内的局部反馈，遮罩属于过度反应。

这三处的进度条仍用**同一份主题 `ProgressBar` 样式**，"外观同源"已达成，无需并入容器。
此例外**不因遮罩新增取消能力而改变**——它们的差别是"非阻断"，不是"没有取消入口"。

**自绘路径（`Path` / `PathGeometry`）的两条硬规则**（踩过坑）：

1. **几何必须从 <c>0,0</c> 起，或给 `Path` 加 `Stretch="Uniform"` + 显式 `Width/Height`**——
   `Stretch` 默认 `None` 时 Path 按**几何自身坐标系**绘制，几何自带偏移（如勾号 `M 4,9 …`）时
   会叠加居中布局的偏移，图形落在框的**右下角并溢出**（复选框勾号的实际故障）；
2. 只用图标字体能表达的形状优先用字形（见上），自绘路径留给"必须精确控制描边/对齐"的小图形。

⚠️ **图标一律显式 `FontWeight="Normal"`**：这一套字体**只有一个字重**，一旦继承到粗体
（`ButtonBase` 等基底样式就带 `SemiBold`），WPF 会做**合成加粗**（fake bold）——不只是变粗，
墨迹还会沿书写方向**向右扩出**、边缘发虚，在窄容器里看着就像"图标右侧被切掉一截"
（实测踩过：WT Live 页工具栏的下载列表图标）。

⚠️ **图标按钮的尺寸不要由字形决定**：FA 各图标的 advance 宽度差异很大——`cloud-arrow-down` 宽、
`arrow-down` 窄，同一个图标按钮在两者之间实测差了 **5.3px**（37.8 → 32.5）。若按钮宽度靠
"字形 + 左右内边距"自然撑开，**换个图标按钮就会跟着胖瘦**，与相邻按钮不再齐平
（实测踩过：涂装管理页页头的下载列表按钮）。做法：把**图标内容区固定成正方形**
（如 `<Grid Width="14" Height="14">`，字形在其中 `HorizontalAlignment="Center"` +
`VerticalAlignment="Center"`），按钮宽高随之固定（如 `Width="34"` + 左右内边距均分剩余宽度）。
尺寸一律用设备无关单位，DPI 缩放时等比放大，不会变形。

**尺寸档**（FA 的墨迹覆盖比 MDL2 大，历史上同位置字号已整体下调一档）：
导航 / 按钮 **14**、行内提示 **15**、对话框图标与缩略图占位 **22**、空状态 **26**、拖入覆盖层 **30**、
标题栏窗口按钮 **12**。

**标题栏窗口按钮**（`TitleBarButton` / `TitleBarCloseButton`）：

- 窗口一律 `WindowStyle="None"` + `WindowChrome` 自绘标题栏，**不用**系统三键；
  四个按钮：置顶 / 最小化 / 最大化 ⇄ 还原 / 关闭，字形写在 `Content`（关闭键写在样式里），
  尺寸 40×28、间距 `2,0`。
- 悬停 = **主题表面色圆角底**（`CornerRadius=6`，120ms 淡入）+ 图标提亮到 `BrushText`；
  按下 = 图标透明度 0.55；关闭键悬停 = **危险色软底 + 危险色图标**。
  悬停底与图标必须是**兄弟节点**（图标放进做透明度动画的容器会连图标一起被隐藏）。
- **置顶**：点一下置顶、再点一下取消；置顶时图标变**主色**以示状态，悬停有提示气泡
  （`app.window.pin`）；仅本次运行有效，不落盘。
- 提示气泡用**主题化 `ToolTip` 样式**（主题表面色底 + 主题边框 + 圆角 6 + 轻投影），不使用系统样式；
  **长提示会自动换行**（样式的 `ContentTemplate` 里带 `TextWrapping="Wrap"`——
  默认字符串内容不换行，会横向溢出气泡外，`MaxWidth` 只约束气泡本身）。
- **仅图标的按钮必须给 `ToolTip`**（没有文字就没有可读入口）；列表行内的小动作优先用
  **`IconButton`**（24×24 紧凑、悬停主题表面色圆角底），文字按钮只在有足够横向空间时使用。

**新增图标时**：优先在同一套字体里找（`Assets/Fonts/` 的字体含 1426 个字形）；
颜色一律走 `Foreground` / 主题画刷（四套主题自动一致）；不要引入位图或系统字形。
新增窗口按钮时同步更新上面的字形表与自检里的码位清单。

## 3. 主题与自定义

- 程序内置**四套配色主题**，设置页「主题」下拉选择：**默认蓝**（§2.1 默认配色）/ **翠绿** / **琥珀** / **深色**（暗色配色）。
- 每个主题是一份**纯颜色字典** `Themes/Theme.<Id>.xaml`（覆盖 §2.1 全部颜色令牌）；画刷与组件样式集中在
  `Themes/ThemeResources.xaml`，按 key 引用颜色令牌。**新增主题** = 新增一份颜色字典 + 在 `Services/Infrastructure/ThemeCatalog.cs` 登记。
- **生效时机：重启**。启动时按 `config.json` 的 `theme` 先合并主题颜色字典、再合并样式字典
  （`StaticResource` 在 XAML 解析时取值，因此不做运行时热切换）；设置页选择后自动保存，并提供「重启程序」按钮。
- **语义色保留**：危险色（Danger 系）在所有主题中保持红色；「已激活」标记在主色为绿的主题（翠绿）下换为蓝色，避免与主色撞色。
- 导出 / 导入主题（复制颜色字典文件）可作为后续扩展。

## 4. 窗口外壳

- **不使用 WPF 自带 Window 操作栏**：采用 `WindowStyle="None"` + `WindowChrome`，自绘标题栏。
  - `WindowChrome` 保留系统缩放边框与阴影，`CaptionHeight=0`、`ResizeBorderThickness=6`。
  - 自定义标题栏高度 36，含：左侧标题文字（绑定窗口 `Title`）、右侧窗口按钮（图标按钮，关闭按钮悬浮变红）。
  - 标题栏区域内按下左键拖动窗口；按钮分别实现最小化 / 最大化（切换）/ 关闭。
- **最大化不遮任务栏**：挂钩 `WM_GETMINMAXINFO`，把最大化边界设为**所在显示器的工作区**
  （多显示器各按所在屏、按物理像素计算）。不修的话自绘外壳最大化会盖住任务栏且四边溢出；最大化时同时去掉窗口 1px 外框（贴边）。
- **拖动最大化窗口 = 还原并继续拖**（标准行为）：光标保持在标题栏上同样的横向比例处；
  **双击标题**切换最大化 / 还原。因此拖动要在 `MouseMove` 过**系统拖动阈值**后才进 `DragMove`
  （在 `MouseDown` 里直接 `DragMove` 会阻塞并吞掉双击）。
- 注意 .NET 10 WPF 下的 DPI 缩放、最大化边界与阴影处理。

## 5. 组件规范

> **过渡动画统一规则**：所有**状态反馈**（悬停 / 按下 / 勾选 / 高亮）的颜色与透明度变化都带过渡——
> **进入 120ms、离开 150ms**（颜色或透明度），按钮按压缩放 0.97（80ms 进入、120ms 回弹）；
> **状态切换**（选中 / 展开）允许直接切换。实现模式 = 触发器保留最终值的 `Setter` + `Enter/ExitActions`
> 里的 `ColorAnimation` / `DoubleAnimation` / `ThicknessAnimation`（开关滑块）。
> ⚠️ 淡出动画的终点必须用 `ColorTransparent` 令牌（随主题取"透明白 / 透明黑"）：
> 写死 `#00FFFFFF` 在深色主题下淡出途中会闪白。
> 注意：动画目标画刷若是共享主题画刷，动画系统会自动克隆，不影响其他控件。

### 5.1 按钮

- **主按钮 `PrimaryButton`**：实心 `PrimaryFill`、白字、高 34、圆角 6、内边距 16。
  - 悬浮 150ms 渐变到 `PrimaryFillHover`；按下变为 `PrimaryFillPressed` 并**缩放至 0.97**（80ms，回弹 120ms）；禁用时整体 50% 透明。
  - ⚠️ 页面默认文字色由**窗口 `Foreground` 继承下发**，**不要**在全局 `TextBlock` 样式里设 `Foreground`——隐式样式优先级高于继承，会把按钮文字强制成深色，压在填充底色上导致不可读。
- **次级按钮 `SecondaryButton`**：白底 + `BorderStrong` 描边、`TextSecondary` 文字。
  - 悬浮底变 `Hover` 且描边转 `Primary`；按压缩放 0.97。
- **导航按钮 `NavButton`**：透明底、`TextSecondary` 文字、高 44、圆角 8、左对齐、图标 + 文字。
  - 悬浮底 `Hover`；**选中态**底 `Surface2`、文字 `Primary`、字重 SemiBold。
  - **折叠态**（`IsNavCompact`，§5.13）：**内边距两态都是 `12`、尺寸一律不动** ——
    折叠只是"窗格围着图标收起来"，图标与标签的左边缘逐像素不变（改内边距会让图标瞬时平移 = 跳一下）；
    标签**不切 `Visibility`**，由模板的 `ClipToBounds` 裁掉（展开时是"滑出来"而不是"跳出来"）；
    只显示图标时**必须**读得懂 —— 文案挂在各导航项的 `Tag` 上，本样式在折叠态把它当 `ToolTip`，
    展开态置空（标签就在眼前，再来一条提示是噪音）。**新增导航项必须补 `Tag`**（自检会数数量）。
- **标题栏按钮**：透明底、固定 46×32；悬浮底 `Hover`（**120ms 颜色过渡**，离开 150ms 回落）、按下图标变淡（0.55）；
  关闭按钮悬浮底 `Danger`（同样带过渡）、图标转白、按下 `DangerPressed`；最大化按钮图标随窗口状态在 `E922` ⇄ 还原 `E923` 间切换。
- **可点复制的字段（超链接）**：`<Hyperlink>` + `Foreground="{StaticResource BrushPrimary}"` +
  `TextDecorations="Underline"`（「关于」页的作者 / 版本 / 构建三行就是这一套）。
  **同一组字段里"能点的"必须样式一致**，点了复制什么只能靠悬停提示区分
  （例：版本行复制"版本号 + **缩略**构建号"，构建行复制"**完整**构建号"——
  两处口径不同，提示里都要写清，别让用户以为复制的是眼前看到的那串）。
  点完一律发一条顶部气泡（§2.7）说明"复制了什么"；被占用 / 失败也要有提示，不许静默。


### 5.2 输入框 `BaseTextBox`

- 高 34、圆角 6、白底、`BorderStrong` 边框、水平内容内边距 6（`Border.Padding` 单次承载，避免文字离边框过远）。
- 悬浮边框转 `BorderFocus`；**聚焦**边框 `BorderFocus` 且描边加粗至 1.5。内容宿主禁用滚动条。
- **只读态**（`IsReadOnly="True"`）：背景 `Surface`、边框 `Border`、文字 `TextSecondary` —— 各退一档，
  一眼看出"这里不能编辑"。用**只读**而不是禁用：路径这类内容还需要能选中 / 复制。
  悬浮与聚焦照旧给边框反馈（它是可交互的字段，只是不可写）。
  **底色只能用 `Surface`（中性灰），不要用 `Surface2`** —— 后者是主题强调色底
  （Blue `#e0ecff` / Emerald `#d8f3e7` / Amber `#fbeed3`），铺在白色卡片上就是一块蓝/绿/黄的输入框，
  实测被用户点名"很突兀"。
  设置页的目录框就是这一态：**路径只能由「更改」按钮走目录选择器改**（手输容易写出不存在的路径，
  而每个目录都牵着迁移 / 服务重配 / 重扫，输错代价不小）。那个按钮用 `SecondaryButton` +
  `Foreground="{StaticResource BrushDanger}"`：它是这一行唯一可写入口，用危险色把它顶出来。

### 5.3 卡片 `Card`

- 白底、1px `Border` 描边、圆角 12、内边距 20、`SnapsToDevicePixels`。
- 阴影：极柔（`BlurRadius=16, ShadowDepth=2, Opacity=0.06`，色 `#0f172a`），仅用于表达层次。
- 页面以卡片分组承载内容（如设置页的「目录配置」「数据表」）。

### 5.4 复选框

- 18×18、圆角 4、白底 `BorderStrong` 描边。
- 选中：底与描边转 `Primary`，显示白色对勾；悬浮描边转 `Primary`。

### 5.5 滚动条

- 细样式，厚 10；轨道 `#EDF1F6` 圆角 4；滑块 `#C7D2DE` 圆角 4，两侧内缩 2。
- 滑块悬浮 `#9AA9BB`、拖拽 `#6B7A8D`；隐藏传统箭头按块（保留翻页）。
- 兼容水平 / 垂直方向。

### 5.6 空状态

- 卡片内：居中/左对齐的**字体图标（30，`TextMuted`）** + **标题（15 SemiBold）** + **说明（13 `TextMuted`）**。

### 5.7 缩略图卡片网格

- **布局**：`WrapPanel`，列数与卡片尺寸由可用宽度计算下发（目标卡片宽 150，间距 12）→ 窗口变化时**列数与卡片尺寸自适应**。
- **卡片**：圆角 10、1px `Border` 描边、缩略图 `UniformToFill`；无预览时中央显示 `TextMuted` 字体图标占位。
- **名称条**：卡片底部**半透明深色**横条（约 70% `#101828`），圆角仅下侧，白字 12、超出省略；**已激活**的包该条改为**半透明绿**（`ActiveStrip` `#CC15803D`）。
- **状态区分**（选中与激活**用不同视觉通道**，避免"既是选中又是激活"时互相遮挡）：
  - **选中** = 外描边 2px **主色蓝**（`PrimaryFill`）；
  - **激活** = 左上角**绿色徽标**「已激活」（`ActiveFill` `#22C55E` 白字）+ **绿色名称条**；卡片网格上方的激活说明文字：**已激活 = 绿**（`Active` `#16A34A`）、**未激活 = 主色蓝**（那只是提示语，不是激活状态）。
- **状态**：选中 = 2px `PrimaryFill` 描边环；悬浮 = 2px `BorderStrong` 描边环。
- **交互**：单击选中、双击打开属性、按住卡片拖到另一张卡片上即**排序**（顺序持久化到各包 `meta.order`）。

### 5.7.1 瀑布流卡片网格（WT Live 浏览）

- **布局**：`MasonryPanel`（`Controls/MasonryPanel.cs`）——卡片**等宽不等高**：列宽由可用宽度算出（目标宽 240、最小 170、最大 360、列数上限 5、间距 16），**卡片高度由内容决定**（缩略图按自身宽高比撑开）。
- **错落规则**：只保证**第一排顶部齐平**；之后每张卡片接在当前**最短的那列**后面（多列等高时取最左列）。与 §5.7 的 `WrapPanel`（整行对齐）是两种观感，不要混用。
- **图片按比例占位（必须）**：缩略图高度 = **图片实际可用宽度** ÷ 图片宽高比（`AspectRatioHeightConverter`）。图片加载完再撑高会让整列重排、滚动位置乱跳——瀑布流最刺眼的抖动就来自这里。
  - 比例只做**异常值护栏**（0.25~6，远宽于正常图片）：占位框比例一旦与实际不符，`UniformToFill` 就会裁边——**任何裁剪都意味着框比例算错了**，不要用"夹取比例"去压制极端图，宁可让那一张卡片真的很高。
  - ⚠️ **宽度必须用图片自己的**（缩略图容器的 `ActualWidth`），**不能直接用列宽**：卡片的内边距 + 1px 描边会让图片比列宽窄（本项目 26px），按列宽算出的框偏高，`UniformToFill` 就会为了铺满高度把图片左右各裁掉约 12%（肉眼可见的裁边）。容器的 `ActualWidth` 首帧为 0，故换算器保留"列宽 − 卡片让出宽度"的兜底值。
- **卡片**：白底 + 1px `Border` 描边 + 圆角 12、内边距 12；缩略图圆角 10（`ClipToBounds` 不认圆角，需在 `SizeChanged` 里设 `RectangleGeometry`，同 §5.7）。**不用 `Card` 样式**：它带阴影，一屏几十张时逐张阴影的开销不值当。
- **缩略图三态**（`WtLiveCardItem.ThumbnailState`）：**加载中 = 加载圈**（`BusySpinner` 缩放到 24、居中）、
  **没有预览图 / 下载解码失败 = 占位图标**（`F03E` image，22 `TextMuted`）、**就绪 = 图片**，三者互斥。
  失败态**不复用加载圈**——一直转会让人以为还在加载（列表一进页面就有几十张图在排队，圈是必要的反馈）。
- **加载超时出口**（`ViewModels/SlowLoadWatcher.cs`，卡片与详情浮窗共用）：加载持续超过 **5s** 时，
  在加载圈**下方**浮现「重新加载」按钮（`wtlive.reload`，次级按钮压到 26 高 / 12 字号），
  点了取消上一趟重下。**不自动重试**：网络慢但正常的一次加载不该被掐掉重来，出口交给用户；
  加载一结束（成功 / 失败）按钮立即收起（`OnThumbnailStateChanged` 里统一收，避免"图都出来了按钮还挂着"）。
  重载 = 取消上一趟 + 重新开始（按钮立刻收起、5s 计时重来）。
  - ⚠️ **命令路径（虚拟化下的铁律）**：行模板里的命令**一律走数据项自己的属性**
    （`{Binding DownloadCommand}` / `{Binding SearchAuthorCommand}` / `{Binding ReloadThumbnailCommand}`），
    **不要**用 `RelativeSource` 去够 VM。这条**适用于所有虚拟化列表的行模板** ——
    WT Live 的卡片（本节）与载具管理页的**部件行**（其「删除 / 恢复」按钮，见 §3.10）都踩过同一个坑：
    行内按钮改用 `Click` + `sender.DataContext`（`sender` 就是按钮自己，始终指得对）。
    两个理由，一静一动：
    ① **静态**：容易少写一层路径（写成 `DataContext.ReloadThumbnailCommand`、漏掉 `WtLive.`）→
       WPF **静默绑定失败**，按钮点下去毫无反应；
    ② **动态、更阴**：瀑布流是虚拟化的，容器滚出视口会被回收（**那一刻脱离视觉树、"没有祖先"**），
       滚回来再复用（重新挂回时解析时机也不定）—— `RelativeSource` 那条链**会踩空**，
       表现为"**偶发**点了没反应"：只在滚动来回之后出现，首屏怎么点都正常，最难复现的一类 bug。
    所以三个命令都在 `WtLiveCardItem` 上暴露、由容器在创建卡片时注入；参数仍从卡片**自身属性**取
    （`PostUrl` / 卡片本身），同样不涉及祖先查找。缩略图高度（`ImageHeight`）当初也是踩了同一个坑
    才改成"面板算好推给数据项"（见 `WtLiveCardItem` 的说明）。
    自检里已用反射把这批成员钉住，并断言三个命令非空。此外自检还会**扫 XAML 文本**：
    定位卡片模板段（用 `Card_MouseLeftButtonUp` 反查 `<DataTemplate>`）后，
    断言段内不出现 `AncestorType` / `FindAncestor` / `ElementName` / `x:Reference`
    （`Self` / `TemplatedParent` 不依赖祖先，属安全写法、不拦）—— 这类写法再被引入就直接报异常。
    护栏还会**自证**"定位到的段确实是卡片模板"（须含 `DownloadCommand`），
    否则"0 处"可能只是扫了个空串。
- **清晰度档位**：设置页「WT Live 卡片图片清晰度」（默认**低清**，见 `Services.WtLiveQualityCatalog`）
  决定下载哪一级 CDN 变体（低清 386px / 中清 800px / 原图），并按**卡片要占的设备像素宽**
  （列宽 DIP × 屏幕缩放）解码——只按 DIP 算，125% / 150% 缩放的屏幕上位图会被再放大一次，看着就是糊的。
  改档只影响之后加载的卡片（重下已显示的 25 张既费流量也压站点），想立刻重载可点工具栏里的「刷新」。
- **右下角「下载」按钮**（`F019` download，`IconButton` 24×24，ToolTip = `wtlive.card.download`）：
  点它直接打开「从 WT Live 下载」确认窗口，**帖子链接已预填并自动读取**（省掉"复制链接 → 粘贴 → 读取"三步）；
  命令回绑 `DataContext.Skins.OpenWtLiveImportCommand`（`RelativeSource AncestorType=ItemsControl`）+
  `CommandParameter={Binding PostUrl}`——与涂装管理页的入口**共用同一个命令**（不传参数 = 空白打开）。
  **没有站内附件的帖子不显示该按钮**（`HasFile=false`，`Visibility` 触发器）：那条路只会得到一句
  "没有可下载的文件"，按钮等于骗人；这类帖子仍可去网页下载后走「导入压缩包」。
  位置在**副标题行右端**（不是压在缩略图上）：该行右侧本来就空着，压图会挡画面、还得新造一层覆盖层样式。
- **状态**：列表为空时居中显示空态（图标 26 `TextMuted` + 标题 15 SemiBold + 说明 13 `TextMuted`）；已有内容时底部按需显示「加载中 / 失败重试 / 已经到底了」，三者互斥。
- **加载方式**：滚动接近底部预取下一页（距底 400px 起触发）；请求**幂等**，加载中 / 已到底 / 失败态重复触发都直接忽略。
- **点击**：整张卡片可点（`Cursor=Hand`，`Border.MouseLeftButtonUp`）→ 打开详情浮窗（§5.7.2）；
  右下角「下载」按钮的点击**不会**顺带打开浮窗（按钮已把鼠标事件标记为 `Handled`）。
- **页头工具栏（右列）**：排序下拉 → 搜索框 → **刷新** → 「收藏的作者」→ **下载列表入口**（最右）。
  **末三个是同一组图标按钮**（34×34，`IconButton` / 无边框变体）：彼此间距 **4**、与左侧搜索框之间留 **8**
  —— 同一组"列表动作"紧排成组，同时与"查询"区隔开；三个都只有图标，必须各带 `ToolTip`。
  下载列表入口与涂装管理页页头是**同一个控件**（`Views/WtLiveDownloadsButton`，见图标表下的「状态着色」）。

#### 5.7.2 详情浮窗（点卡片打开）

- **入口**：点卡片任意位置 → `WtLive.Detail.OpenCommand`（`ViewModels/WtLiveDetailViewModel.cs`）。
- **形态**：**遮罩浮窗**（`Views/WtLiveDetailOverlay.xaml`），开成独立窗口——浏览是"看列表"的延续，
  弹新窗口会让人以为离开了页面；浮窗还能让「下载确认窗 + 全局处理中遮罩」继续压在最上面。
- **层级**：`Grid.Row=1`（**只盖内容区**，标题栏的窗口按钮保持可用）+ `Panel.ZIndex=40`；
  全局处理中遮罩是 50、拖入提示是 0 —— 详情永远在"处理中"之下、页面之上。
- **尺寸**：卡片 `HorizontalAlignment=Stretch` + `MaxWidth=820`，外边距 48/40，高度铺满内容区
  （`VerticalAlignment=Stretch`）。宽度**必须 Stretch、不能 Center**：Center 时卡片宽度会退化成
  内容期望宽——低清缩略图只有 386px、文案又短时浮窗被压成一根细条，且原图加载完还会再撑开。
  内部：轮播格 `*` + `MinHeight=140`（占剩余高度），正文框 `MinHeight=80` / `MaxHeight=180`
  （长约 12 行，超出框内滚动）——正文长多少，图就让多少，两边都不挤。
- **压暗底**：主题背景色 + `Opacity=0.72`（与 §2.6 处理中遮罩同一配方，四套主题自动一致）。
  **点压暗底关窗必须挂在 `MouseLeftButtonUp`（不是 Down）**：Down 里关窗会让浮窗当场 `Collapsed`，
  同一次点击的 Up 就落到遮罩下面那张卡片上，"点空白退出"会变成"打开了另一个详情"；
  Up 由浮窗自己收下并标记 `Handled`，底下卡片完全收不到这次点击。
- **内容**（自上而下）：预览图轮播（右上角关窗图标）→ 标题 / 作者 / 文件 / 互动统计 →
  正文（只读可复制、限高 110 内滚动）→ 底部动作（左：在浏览器中打开；右：下载）。空的信息行自动收起。
- **关窗**：浮窗**右上角**的图标按钮（`F00D` xmark，`IconButton` 28×28，ToolTip = `common.close`），
  垫一层 `BrushSurface` + `Opacity=0.92` 的圆角底——图片深浅不定，纯图标会有一半场合看不清。
  与 Esc、点压暗底三条路等价；底部按钮行**不再放关闭**（动作区只留"要做什么"）。
- **下载按钮**：走既有的「从 WT Live 下载」确认窗（链接**预填并自动读取**，与卡片按钮同一个命令）；
  **没有站内附件时置灰**，信息区的"文件"行会写明原因（复用 `wtlive.noFile`）。
  **下载真的开始后浮窗自行关闭**（`SkinsViewModel.WtLiveDownloadStarted` → 宿主收起详情）：
  用户此刻要看的是下载进度，不该再回落到详情界面；在确认窗取消、或在「已下载」提醒里选"不再下载"
  都不算开始，浮窗照旧留着。
- **轮播**：**滚轮切换**、左右箭头按钮、`←` `→` 方向键，三条路都走 `Step()`（**环绕**：末张往后回第一张）；
  多张时右下角显示「滚轮切换 · 2 / 4」，单张时不显示箭头与计数。
  滚轮处理器**挂在轮播格里**（不是遮罩根节点）并 `e.Handled = true`：挂根节点会把正文文本框的
  滚动一起吃掉——正文很长时"滚轮滚文本"比"滚轮翻图"更需要能用。
- **图片按需加载**：只看当前这张 + 预取下一张，解码宽度 1280（≈ 640 DIP × 200% 缩放）；
  第 0 张先垫**列表已解好的缩略图**（不空窗，注意标记 `IsPlaceholder`——否则"已经有图了"会把原图那趟
  挡掉，图会一直停在低清），原图到了再替换。关窗即清空（原图解码后每张数 MB）并取消在途下载。
- **加载超时出口**：与卡片同一条规则（`SlowLoadWatcher`，5s）——转够 5s 在圈下方浮现「重新加载」，
  点了取消当前这张的上一趟并重下（`ReloadImageCommand`，按槽位取消，不影响其它张）；单张加载结束即收起。
- **信息分两层**：卡片已有字段**先把浮窗填满、立刻可看**（不等网络），帖子详情拉到后再覆盖更全的
  正文 / 附件 / 统计；详情拉失败只影响补全（给「重试」），卡片那层照常显示。
- **键盘**：`MainWindow.OnPreviewKeyDown` 闸门——浮窗开着时 `Esc` 关窗、`←` `→` 切图并标记 `Handled`，
  **其余按键放行**（正文要能复制、Tab 要能用）；与处理中遮罩"吞掉所有按键"是两套策略，别合并。

#### 5.7.3 「从 WT Live 下载」确认窗

- **入口**：两个，**共用同一个窗口**（`Views/WTLiveImportWindow`）与同一个命令
  （`SkinsViewModel.OpenWtLiveImportCommand`，带参 = 预填）——涂装管理页页头的按钮**空白打开**等粘贴；
  WT Live 页的卡片 / 详情浮窗下载按钮**预填链接并自动读取**（省掉"复制 → 粘贴 → 读取"三步）。
- **结构**（自上而下）：网址输入 + 「粘贴」/「读取」→ 帖子信息（作者 / 文件名与体积 / 下载数 /
  显示名可改 / 描述）→ 底部：提示行 + 「**一键导入**」复选框 + 「开始下载」。
- **「一键导入」复选框**（文案 `wtlive.autoImport`，ToolTip = `wtlive.autoImport.hint`）：
  勾选后**下载完成直接静默进入导入** —— 跳过导入预览窗（`RunImportAsync(silent: true)`），
  **且全程不弹加载遮罩**（由 `BusyIndicator.Suppress()` 作用域抑制，见上文「处理中遮罩」一节），
  导入结果只在主窗口顶部提示一条（`wtlive.imported`）。
  **默认不勾、记住上次选择**
  （`AppConfig.WtLiveAutoImport`：开窗时预置初值，点「开始下载」后回写；**取消关窗不落盘**，记忆保持原样）。
  选择记在**下载条目**上（`WtLiveDownloadItem.AutoImport`），所以点「重试」整条重跑时仍沿用当初的选择。
  **静默导入不记录**「删除源 / 删除压缩包」勾选 —— 用户没在预览里确认过，不该覆盖他上次在预览窗里的选择。
- **布局**：复选框贴左、「开始下载」（`PrimaryButton`）贴右，同一排 —— 左边是"下载完怎么办"的选项，
  右边是动作，主按钮仍是视觉终点。信息区未读出时整段收起，窗口按内容紧凑显示。

### 5.8 开关（Switch）`ToggleSwitch`

- 用于**二选一**的状态切换（如涂装包属性里的 `replace_tex` ⇄ `set_tex` 写入方式）。
- **轨道** 38×20、圆角 10，关 = `BorderStrong`，开 = `PrimaryFill`；**滑块** 14×14 白色圆形，两侧内缩 3。
- 悬浮时轨道不透明度 0.85；**禁用**（不适用时，如该部件选了「无」）不透明度 0.4 且光标为箭头。
- 两侧可配**状态标签**：当前生效的一侧用 `Text` + SemiBold，另一侧用 `TextMuted`（如 `replace_tex [开关] set_tex`）。
- 破坏性/专业性较强的开关，首次使用应弹窗说明含义，用户确认后不再提示（见 `软件功能设计.md` §3.6）。

### 5.9 消息对话框 `MessageDialog`

- 程序中**不使用系统 `MessageBox`**：所有提示 / 确认统一走 `MessageDialog`（`Services/Infrastructure/MessageDialog.cs` + `Views/MessageDialogWindow.xaml`），保证与主界面同风格。
- **结构**：自绘标题栏（40，可拖动，右侧关闭按钮）→ 内容（图标 26 + 正文 13 `TextSecondary`，超长自动滚动，最大高 330）→ 底部按钮右对齐。
- **尺寸**：宽 460、高度自适应（`SizeToContent=Height`、`MaxHeight=640`），`ResizeMode=NoResize`，`CenterOwner`。
- **图标语义**：`Info` ⓘ / `Question` ?（`Primary`）；`Warning` △（`Warning` 琥珀）；`Danger` ⊘（`Danger` 红）。
- **按钮**：主按钮默认 `PrimaryButton`；**破坏性确认**（删除 / 清除）用 `DangerFillButton`（实心红底白字，`Danger` → 悬浮 `DangerHover` → 按下 `DangerPressed`，含 0.97 按压缩放）；次按钮（取消）`SecondaryButton`；仅提示时隐藏次按钮。
- **文案**：标题缺省「提示」；按钮文案由调用方指定（如「删除」「继续」「清除」「我已了解」），全部来自语言文件。

### 5.10 标签（Tag）

- 用于**只读**的简短分类标注（如涂装包属性里按命名推测的「主体」「法线」）。
- 样式：胶囊（`Tag` 样式：圆角 9、内边距 7×2、字号 11、1px 描边），相邻标签间距 4。
- **文案**：短标签，**不写括号补注**（如「喷气尾焰（马赫环）」→「喷气尾焰」），避免标签撑得太长。
- **色调**（按 `TagTone`）：四种色调**统一为「浅底 + 同色描边 + 深色字」**——
  - **部位 / 功能 = 默认（蓝）**：底 `#DBEAFE` / 边 `#2563EB` / 字 `#1D4ED8`；
  - **纹理（`_n`）= 绿**：底 `#DCFCE7` / 边 `#22C55E` / 字 `#15803D`；
  - **法线（`_c`）= 黄**：底 `#FEF3C7` / 边 `#F59E0B` / 字 `#B45309`；
  - **武器 / 导弹 = 红**（内置武器表确认）：底 `#FEE2E2` / 边 `#EF4444` / 字 `#B91C1C`；
  - **跨载具 = 紫**（候选来自其他载具，§3.6「跨载具复用」）：底 `#EDE9FE` / 边 `#8B5CF6` / 字 `#6D28D9`；
  - 目的是让人在部件列表里**一眼区分**贴图类型与武器部件；受损、环境遮蔽等其余类型沿用默认蓝。
- **标记类标签也用同一套胶囊**：载具管理页部件行的「手动」（§3.10 手动补出的位置）与属性页的跨载具 /
  多源标注，都写成 `Border` + `BasedOn="{StaticResource Tag}"` + 该色调的三支画刷（`BrushTagCross*` / `BrushTagWeapon*`）
  + 字号 11 的同色深字，**不要另起一套小方块**（`CornerRadius=3` + `Surface2` 底的那种）——
  混在部件标签里一眼就能看出"不是一套"。「手动」用**紫**：它与跨载具候选是同一件事的两端（补出来的位置
  正是要拿跨载具贴图来配）。
- 与 `ChipButton`（可点击的国家横条胶囊，有选中态）区分：标签**不可交互**，无 hover / 选中态。
- 一行最多 2 个，按重要性从左到右；识别不出就不显示，不占位、不留空标签。

### 5.11 输入框 + 候选气泡（`AddPartWindow`）

- **本体是普通 `BaseTextBox`，不要用可编辑 `BaseComboBox`**：`BaseComboBox` 的模板里**没有
  `PART_EditableTextBox`**，而那块铺满整格的 `ToggleButton` 又把按下全吃掉 —— `IsEditable="True"`
  形同虚设，表现是**点不进去、也打不了字**。要"输入 + 候选"，就用输入框 + 下面这条气泡浮层。
- **候选 = 气泡浮层**（做法同 WT Live 搜索框的下拉，§5.7.1）：`Popup` + `Border`（底 + 1px 描边 +
  圆角 8 + 投影，与主题 ComboBox 下拉同一套）+ `WrapPanel` 排一列**圆角胶囊**（底 `Surface2`，
  悬停转 `Surface`），点一项即把名字回填进输入框。宽度绑输入框 `ActualWidth` → 左边缘对齐。
- **锚在输入框自己身上**（`PlacementTarget="{Binding ElementName=…}"`）：不用 `RelativeSource
  AncestorType` 那种"按树找"，也不要用 `x:Reference` 指祖先（会构成循环依赖）。
- **`StaysOpen="True"` + 气泡 `Focusable="False"`**：点气泡不会把焦点从输入框抢走，否则会
  "先收起浮层、这次点击落空"。收起改由输入框的 `LostKeyboardFocus` 管。
- **用 `Popup` 而不是内联面板**：Popup 不吃布局高度 → 候选出现 / 消失都**不会让窗口跳动**
  （本窗是 `SizeToContent=Height`，内联面板会让框随每个按键长高又缩回）。
- **无候选 / 无输入就收起**：一片空气泡比没有浮层更让人困惑；没有候选时照常手输（候选只是补全便利）。
- **入口按钮「+」紧贴所在小节的标题**（横向 `StackPanel`：标题 + 按钮），**不要右对齐**：
  它是对**这一节**的附属动作（往"部件结构"里加一条位置），飘到行尾会被看成一个全局操作。
  左距 2 即可 —— `IconButton` 是 24 的格子、字形居中（左右各留约 5），再贴就咬到字了。

### 5.12 分段存储条（设置页「存储维护」）

把"这块盘被谁占了多少"画成一根条：**全长 = 该磁盘总容量**，三段 = **本程序资源目录占用 /
该磁盘其他内容占用 / 剩余可用**（数据见 `Services/Storage/StorageUsageService`）。

- **三段共用同一个分母**（该磁盘总容量），且"其他占用"由 `总量 − 本目录 − 剩余` **推**出来 →
  三段相加恒等于全长，条上不会出现"没画满 / 溢出"的缝隙或色带；
- **宽度走星宽**：三段各自是 `Grid` 的一列，`ColumnDefinition.Width` 绑 `占比` 经
  `Controls/ProportionToStarLengthConverter` 换算成 `GridLength(…, Star)` —— 条随卡片宽度自适应，
  不必把条的像素宽回推到 ViewModel，也不必监听 `SizeChanged` 重算。（`ColumnDefinition` 不在可视化树里，
  DataContext 是否流到它身上**已由自检实测钉住**：三段星宽 = 0.4 / 0.2 / 0.4。）
- **配色**：本程序占用 = `Primary`（强调"我们的占用"）；其他内容 = `BorderStrong`（中性深色，与主色
  区分明显）；剩余可用 = `Surface2`（轨道底色，**不另画一层** —— 条的空余部分天然就是"剩余"）。
- **尺寸**：条高 14、圆角 6、1px `Border` 描边；三段底色是直角，两端由 code-behind 在 `SizeChanged` 里挂
  `RectangleGeometry`（半径 = 6 − 1px 描边 = **5**）裁进圆角轮廓 —— WPF 没有内建圆角 `Clip`（同 §2.7）。
- **图例**：三行共用一个 `Grid` 的列（色块 + 名称 / 数值 / 占比右对齐），数值与占比各占一列，
  占比用 `TextMuted`、保留 1 位小数（占用很小时 `0%` 看不出区别）；
- **文字口径**：`P1` 与 `FormatSize`（到 TB 档）都走现有实现，不另起一套格式化；
  磁盘行写明**卷根 + 总容量**（不然不知道说的是哪块盘）。
- **重测入口**：统计要递归枚举整个资源目录，所以**进设置页 / 回收完成 / 换资源目录时**在后台自动重测，
  卡片右上再给一个 `IconButton`（`F021`）手动重测，统计中置灰（置灰本身就是"进行中"的反馈）。
- **卡片里不放任何动态文字**（踩过：说明行一会儿出现一会儿消失，会把下面「立即回收未引用贴图」按钮
  顶得上下跳）。统计进度与"读不到磁盘信息"一律走**顶部气泡**（§2.7）：
  - **开始**：只有**用户主动点重测**才弹"正在统计…"（顺带重测不弹，否则每次进设置页都刷一条噪音）；
  - **收尾**：**主动点的一定给**"统计完成" —— 气泡只活 3 秒，扫描比它久时"正在统计…"先过期，
    再没有下文就会被当成卡死；顺带重测只在这趟超过 `StorageMeasureNoticeDelay`（1.5 秒）
    确实慢到会被察觉时才补一句，快的那些由条自己出现来交代；
  - **读不到磁盘信息**：无论哪条路径都弹一次 —— 那时条会整块收起，不说明就成了"静默消失"
    （同「已知问题」KI-003 的教训）。

  没有能画的数字时条形整块收起，卡片高度只随它出现一次。

### 5.13 左侧导航折叠与响应式

左侧导航可以**折叠成只显示图标**（窗格 220 → 68，图标在窗格里居中且**位置与展开态完全一致**），
展开即恢复完整显示。

- **状态分两层，别混**：
  - `IsNavCollapsed` = **用户的选择**，持久化在 `config.json` 的 `navCollapsed`（默认展开）。
    折叠是"我给内容区让路"的**长期偏好**（窄窗 / 小屏用户会一直用），所以重开程序保持；
  - `IsNavCompact` = **界面实际呈现**的形态 = `IsNavCollapsed || 窗口不够宽`（派生，不落盘）。
    视图只看这一个属性（窗格宽度 / 图标内边距 / 悬停提示都由它驱动）。
  分成两层是为了：**拉宽窗口能自动回到用户要的形态**，而不是"窗口一窄就悄悄改掉用户的选择"。
- **响应式阈值 `NavExpandMinWidth = 920`**：展开态要在 220 导航之外再放下
  「28 边距 ×2 + 620 表单 + 20 余量」= 220 + 56 + 640，窗口窄于这个宽度就**自动紧凑**。
  620 是全应用最宽的固定内容（设置页表单列；原先它右边还有一列「关于」，迁到「关于」页后
  设置页收成单列，这个阈值也随之从 1020 降到 920）。
  此时折叠按钮**禁用**并给出说明（"窗口太窄，展开会挤压内容区"）—— 展开也没有意义，
  与其点了没反应，不如说清为什么。窗口下限仍是 `MinWidth = 900`（紧凑态下内容区 900 − 68 − 56 = 776，够用）。
- **图标可识别性**：折叠后只剩图标，**每个导航项都必须能读出"它是什么"** ——
  文案挂在导航项的 `Tag` 上，`NavButton` 样式在折叠态把它当 `ToolTip`、展开态置空；
  自检会数「导航项数 == 带 Tag 数」，漏一个就判失败。字形沿用同一套 14px FA 图标，不换图标（换图标=换认知）。
- **折叠时图标一像素都不许动**（踩过）：折叠态的窗格宽度取 **68 = 10 外边距 + 12 内边距 + 24 图标格
  + 12 内边距 + 10 外边距**，内边距**两态都保持 12** —— 于是图标（与标签的左边缘）在展开 / 折叠下
  位置完全相同（都在 22），窗格只是围着它收起来。
  早先按"图标在窗格里居中"取 64、并把折叠态的内边距收到 10：图标虽然居中，但切换时**瞬时左移 6px**，
  观感就是"图标会跳一下"。**居中是结果，不动才是要求** —— 68 同时满足两者（左 22 / 右 22）。
- **内边距取 12**（导航项左右内边距；原 16）：导航项是窄条，16 显得空，收到 12 后图标落在 22、
  与「导航」小标题同一竖线；左右外边距仍为 10。折叠态窗格据此从 76 收到 68。
- **宽度与标签是同一个动作**：标签**不切 `Visibility`**，靠窗格 + 模板的 `ClipToBounds` 裁掉
  → 展开时标签随宽度"滑出来"，不会出现"先跳字、再变宽"（也省掉每个导航项一份重复触发器）。
- **宽度初值必须来自绑定**（`NavPaneWidth`），不能只靠动画：WPF **初始帧不执行 `EnterActions`**，
  只写动画的话"上次是折叠态"启动时会先画成 220 再收起来（闪一下）。
- **折叠按钮的位置在两态下都固定在右上角**（同一行里 `*` + `Auto`，标题收起按钮不动），
  手感一致；字形 `F053`（收起 ⇄）/ `F054`（展开）随形态切换。

## 6. 动效规范（Motion）

| 场景 | 效果 | 时长 / 曲线 |
|------|------|-------------|
| 窗口加载 | 内容整体淡入（`RootBorder.Opacity` 0→1；**动画内部根容器，不动窗口自身的 `Opacity`**——窗口级 `<1` 会走分层窗口，首帧实色闪烁） | 300ms |
| 页面切换 | 淡入 + 自下方上移 10px | 250ms，`CubicEase EaseOut` |
| 按钮悬浮 | 背景颜色过渡 | 150ms；复原 200ms |
| 按钮按下 | 缩放 0.97 → 1 | 80ms / 120ms |
| 输入框聚焦 | 边框颜色过渡 | 150ms |
| 滚动条滑块 | 颜色变化 | 即时 / 短过渡 |
| 气泡提示（§2.7） | 出现即显示，底部进度条 3 秒内从 0 长到满 | 进度条与展示时长同值（`ToastService.DefaultLifetime`） |
| 导航折叠 / 展开（§5.13） | 窗格宽度 220 ⇄ 68（**只动这一个值**：图标与标签的左边缘不变，标签随宽度被裁出来 / 裁进去） | 200ms，`CubicEase EaseOut` |

**原则**：
- 只动**透明度 / 位移 / 颜色 / 缩放**，不动布局尺寸（避免抖动与重排）。
- **唯一例外：导航折叠 / 展开**（§5.13）—— 它的语义就是"窗格占多宽"，不动宽度反而没有过渡可言；
  所以只动**导航窗格这一个值**（内容区跟着重排是折叠的固有代价），时长压到 200ms、
  不用 Spring / 不回弹，避免内容区被拉着来回抖。
- 页面切换动画由「选中项变化」触发，不依赖初始加载触发（规避 WPF 初始 `EnterActions` 不执行的问题）。
- 动效不得阻塞交互；取消动画后界面仍应完全可用。

## 7. 国际化（界面文案）

- 程序所有**界面文字使用语言文件**，可替换（功能设计 §3.9）。
- 语言文件位于**程序配置目录**下 `lang/<culture>.json`（如 `zh-CN.json`），**JSON**，key **按功能分命名空间**便于扩展：`app.` / `nav.` / `common.` / `settings.` / `skins.` / `vehicles.`。
- 界面通过标记扩展 `{loc:Loc key}` 引用文案；切换语言时界面自动刷新。
- key 缺失时显示 `⟦key⟧` 以暴露未翻译项；不得在界面代码中硬编码中文文案。
- **同一个 key 不得在语言文件里定义两次**：反序列化成 `Dictionary` 时**后者静默覆盖前者**（不抛异常），
  被覆盖的那条永远不生效、界面显示的是另一处的文案。实测踩过：`wtlive.list.empty` 同时被写成
  "没有找到涂装"与"暂无 WT Live 下载"，于是 WT Live 浏览页**空态**显示成了下载列表的那句。
  自检直接数**原始 JSON** 的属性名（键齐平 / XAML 里 key 存在这两条检查看不见它 —— Dictionary 早就去重了）。
- **代码里按字符串取 key**（`Loc["…"]` / `Loc.Format("…")`，含 `LocalizationManager.Instance["…"]`）也在自检范围内
  （扫 `.cs`，`XAML 文案` 那条只看得到 `{loc:Loc}`）：写错一样会显示 `⟦key⟧`，实测踩过——确认按钮取了
  `common.confirm`，而表里只有 `common.ok`。**按钮文案统一取 `common.ok` / `common.cancel`**。
- 设置页可**切换界面语言**（内置支持 + `lang/` 目录下的语言文件）；**下拉显示名 = 语言文件内自己声明的
  `app.language.name`**（语言自己写自己，缺失回退语言代码）；切换即时刷新全部 `{loc:Loc}` 绑定，
  **派生文案同步重算**（载具自动译名按新语言检索、国家名重建）。

## 8. 与实现关联

- 设计令牌与所有组件样式集中在资源字典 `Themes/ThemeResources.xaml`，由 `App.xaml` 合并注入。
- 令牌以颜色 / 画刷键形式提供（`ColorPrimary`、`BrushPrimary`、`Card`、`PrimaryButton`、`BaseTextBox`、`NavButton`、`ScrollBar` 等），组件通过 `StaticResource` 引用 → 换肤零成本。
- 自定义窗口外壳在 `MainWindow`（`WindowChrome` + 自绘标题栏）实现。
- 语言文件与标记扩展见 `Services/Infrastructure/LocalizationManager.cs` 与 `Localization/LocExtension.cs`。
- **语言表约定**（新增文案前先过一遍；自检里的 `措辞体检` / `术语一致` 会兜底）：
  - **术语表**（同一东西在两种语言、所有页面里必须是同一个词）：
    涂装包 = skin package、涂装 = skin、部件位置 = part position、贴图 = texture、载具 = vehicle、
    资源库 = resource library、数据表 = data table、用户表 = user table、输出 = output。
    **例外的只有游戏自己的概念**：`part.tag.camo` 的「迷彩」与 `set_tex` 的说明说的是游戏里的 camo 纹理，
    那层就该叫 camouflage —— 自检把这两个键列为允许项，别处出现即判分裂。
  - **引用 vs 数据**：引用界面上的文案 / 按钮用**单引号**（`'Export'`、`'Settings'`）；
    引用用户自己的数据（涂装名、路径、标识）用**双引号**（`"{0}"`）。中文统一用 `「」`。
  - **英文按钮/选项**用 Sentence case（`Check for updates`、`Rebuild the whole library`），
    表头按同表既有风格（`Part Position` / `Used Texture` / `blk Blocks`）。
  - **计数不能靠 `(s)`**：英文单复数没有规则可套时改成**不计数说法**（`Packages: {0}`、
    `files deleted {0}`），既不出 `1 packages` 的错，也不用为此加一套复数规则。
  - **拼在主体句后面的"尾注"键**（`import.cleaned`、`skins.syncWarnings` …）必须**自带前导分隔符**
    （`; ` / `；` / 外层括号）—— 它们靠字符串拼接，少了分隔就会连成一串；自检 `追加片段` 会拦住。
- **剪贴板访问一律走 `Services/Infrastructure/ClipboardService.cs`**（自检会扫源码，别处直接调 `Clipboard` 即判失败）：
  写文本用 `Clipboard.SetDataObject`，**不要用 `Clipboard.SetText`** —— WPF 那个实现会把字符串包成
  "UnicodeText + Text + OEMText + Locale"多格式 DataObject 再 flush，实测经常抛 `CLIPBRD_E_CANT_OPEN`
  （**文本其实已经写进去了**，却要卡约 1 秒），更麻烦的是它在这种"半成功"状态下**会把剪贴板留着不放**：
  用户看到的现象是"其他程序一直提示剪贴板被占用"，直到本程序退出。换成单格式 `SetDataObject` 后不再出现。
  这套口径 2026-10 在用户机器上逐条量过（该机器上似乎有剪贴板监视类程序：**写完约 1 秒内连读
  都打不开**，所以下面每条都是被实测推翻过的教训）：
  - **写入必须在常驻 STA 线程上做（`SetTextAsync`），UI 线程一次都不碰** —— 一次访问实测可能
    被 OLE 拖到 916–943ms，在 UI 线程上就是用户报的"点一下卡约 3 秒"。该线程**必须常驻 + 带消息泵**：
    不 flush 的写入靠**本进程延迟渲染**供数据（线程一退数据就没了），别的程序来取数据也要有人应答。
  - **写入分两步，顺序不能反**：先 `copy: false`（实测 **32ms、不抛错**，立刻可粘贴），
    再在后台**补一次** `copy: true`（flush，数据归系统所有 → 本程序退出后别人仍能粘贴；实测这台机器
    要 **943ms 才抛错**，所以只在后台做、且加序号防止"补旧内容"盖掉用户之后新复制的）。
    先 flush 再兜底是错的 —— 每次复制都要先白等近 1 秒。
  - **成败只看"不 flush 那一步抛没抛"**：flush 会在**数据已写进去**之后抛 `CLIPBRD_E_CANT_OPEN`
    （按它判会给出"弹失败、其实复制成功"的假警报），而"写完立刻读回"也不可用（那 ~1 秒内连我们
    自己都读不到，实测同一时刻的 `Clear()` 也打不开剪贴板）。`copy: false` 不抛 = `OleSetClipboard`
    成功 = 数据确实在剪贴板上；抛了才报失败 —— 两边都诚实。
  - **任何一侧都不重试**：既然每次访问都可能被 OLE 拖到约 1 秒，重试就是纯放大（上一版重试 5 次，
    用户实测"卡死好几秒"）。读取类接口（读文本 / 读图片）同样只试一次，读不到就如实报
    "没有 / 稍后再试"，让用户再点一下。
  - **不要用 `Clipboard.SetText`**：它把字符串包成多格式 DataObject 再 flush，更容易失败，
    失败时还会把剪贴板留着不放（"其他程序一直提示剪贴板被占用"）。
